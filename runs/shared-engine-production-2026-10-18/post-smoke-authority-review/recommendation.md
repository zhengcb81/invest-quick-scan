Reuse the existing original budget table, immutable cell association, native intent join, owner OS principal and per-POST guards. Replace the fixed source pair **only in the new dialect** with a bounded list of retained-exposure references. Each entry derives its exact original policy/physical attempt, status, reservation, cash-null state and transport proof from the original ledger. Native sources must additionally derive original pack/single work members, intent/request/receipt hashes and current no-resend disposition from original native records. A caller cannot assign “not sent,” “invalid,” “settled” or “disjoint” by JSON. Missing finish/validation details remain missing. Current original owner policy explicitly acknowledges the retained risk for one exact future action; a digest/reference alone is never a grant. Quote and POST must reject omissions of any currently blocking exposure or any changed source snapshot.

Accepting retained risk means only a narrow exception to the reconciliation **pause** for that approved independent action. All101 original request counts, all reservations, unknown cash, the old inflight slot, route/group/global capacity and hard cost/request caps still participate unchanged. Never call `reconcile_budget_attempt`, clear old work or mark an unpriced cost as spent merely to proceed. The new original request becomes102 only when the actual original SDK send occurs.

Bind a genuine `company-scan-task/1.0.0` and its execution-profile hash to the newly approved action. For the first delivery, accept exactly one real subject and one actual native-compatible pack of1–12 original questions, zero external search, explicit thinking/output caps and an actually qualified original route. Retain old task1/2/3/research1.1 branches and their frozen comparison behavior byte-for-byte.

Keep **integrity identity** separate from **semantic deduplication**. Bind the full profile/native group hashes for tamper detection, but do not allow run/cohort/task/work/generation IDs or opaque profile hashes to make the same comparison “new.” Use a versioned semantic projection of exact subject, original question/body/module bindings, actual cutoff, pack membership/strategy, route/model, reasoning/output/search controls and explicit replicate ordinal. Actual cutoff belongs in that semantic projection; full profile hashes may contain incidental original group/authority details. This avoids both accidental duplicate sends after rewrapping and permanent blocking of a genuinely later information date.
