1. Prepare the actual original ApprovedRefreshSession/QuickScanWorkLifecycle through the already-installed native owner APIs. Keep the original namespace, work store, current permissions, route and budget. A JSON task/profile never creates authority.
2. Call shared_company_task.create_company_scan_task(lifecycle, experiment_id=..., run_id=..., question_ids=approved_subset, evidence_board={"records": [...]}, pack_by="module"|"dimension"|"single", max_questions_per_pack=1..12, limits=...). Non-MiMo routes require an explicit singleton cap. Use only endpoints/models qualified by the original StockQA ResearchChatSession; a singleton cap does not qualify arbitrary providers. No model/base-URL substitution or duplicate SDK registry exists here.
3. Pass the resulting task and same lifecycle/client to original OwnerResearchServices(native_session=False). Call shared_company_engine.execute_shared_engine with the original bounded session configuration. The new preflight matches all original input references, actual company/runtime projection, native grouping and selected route, and refuses SDK configuration exceeding task/profile resource caps. Original exact comparison_controls must match every actual packet, not merely the largest packet.
4. Treat task/board/company/runtime as immutable. The factory canonical byte references are checked before requests and checkpoint restore. To populate evidence after learning the derived company_ref, create an empty-board task to get that stable ref, construct records and call the factory again with evidence_board; do not mutate the returned task. Keep unknown dates/units/claims unknown; unsupported or after-cutoff records are refused, and unverified records cannot justify a score.
5. Keep the stable task/profile and original intent across restart. Use resume_shared_engine with the same admitted native owner and fresh services observer. Recovery reads original safe visible output; unknown or absent output pauses instead of resending. Finished one-shot packets are not asked again automatically when a received answer is malformed. Partial remains partial; owner controls govern any later separate comparison/repair action.
6. Export/report uses the new scan-run/checkpoint protocol and execution-profile.json. The original checkpoint task bundle and original event replay verify profile/question/cutoff/source body refs. Align profile version, questions/module locks, actual cutoff, model and evidence before comparing companies or time. Do not mix profile scans into the frozen12-question experiment comparison by file extension alone.

Defaults remain conservative; an explicit scan request ceiling may be raised to128 model requests, still bounded by original native owner/ledger controls. For17 singleton packets, explicitly request enough model-request capacity. SDK output/input/wall parameters must fit the profile caps; do not silently reduce a native owner's exact approved parameter to make a mismatch pass.

Not supported in this slice: multi-turn packets, native_session=True research, search requests (cap0), expired-lease answer renewal, hidden-conversation recovery, or official search-backed answer checkpoint. Original SDK qualification, private reasoning handling and per-POST current owner/budget/work guards remain mandatory. This carrier/profile cannot clear or exclude old unknown/unpriced liabilities or install a real grant.

One exact full SubjectRef is required per task. Distinct listing, segment, or business perimeters require separate original approved tasks; the scan carrier does not merge them.
