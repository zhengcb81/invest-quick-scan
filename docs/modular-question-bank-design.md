# 组合式快扫题库：模块、路由与升级契约

2026-09-26 设计增补。目标是对约2,000家独立上市公司用有限问答完成可追溯画像，并允许单个模块独立扩题。本文是待实施契约，不能把任务卡或离线校验视作生产接线完成。

## 复用现状与唯一题库

`questions/catalog.json` 已列出48个JSON模块、222道评分题：`common` 24题，类型、行业、阶段、属性与杜邦/五力/恢复诊断。`scripts/question_sets.py` 已按这些轴组合、处理类型替代、输出manifest；事实题库也已经有适用性选择。继续演进这套文件和CLI，不建立第二份模块目录、第二个执行器或在skill内调用LLM。StockQA承担搜索和问答，StockWiki保管成员、路由快照与不可变观察。

例：某已商业化半导体公司处于快速扩张期，选`common + operating + semiconductors + scaling`；若客户高度集中再加`concentrated`。若处在周期低谷，可同时加`cyclical + recovery`，不强迫把阶段改为`turnaround`，也不因目前低分抹掉护城河证据。这里的`scaling`指经营生命周期，不依据股价涨幅或市场风格给“成长股”贴标签。银行、保险等类型题只替换有会计口径冲突的核心题，不取消核心构念。

## 模块清单与升级边界

现有每个模块已有`module_id/kind/version/name/applies_when/questions`；下一版在原结构上增补机器可核对的元数据：`axis`（类型/行业/阶段/属性/诊断/投资视角）、`activation`（必要证据、阈值、可选条件）、`scope`（实体/证券/分部）、`dependencies`、`conflicts`、`priority`、`introduced_in`、`deprecated_in`、`supersedes`。序列化契约以`conflicts`为唯一排斥字段名，不接受`excludes`别名。客观公司属性可按证据选用；“投资视角/范式”默认由用户或保存的策略显式启用，不让LLM把研究偏好伪装成公司属性。catalog登记可用模块及路径；发布锁文件逐模块记录版本、文件SHA-256、题ID/题义指纹、路由器版本与兼容区间。注册新模块时必须通过schema/唯一ID/引用/冲突、`scoring-contexts`渲染口径和事实覆盖检查，不能靠在路由提示词里加一行隐式生效。

版本规则以**题义和可比性**为中心：模块新增独立问题时升次版本，旧题ID、构念、锚点与评分方向原样保留；同ID的已发布题面/证据/锚点一律不可改，连文案勘误也用新题ID及`supersedes`关系，旧题留在历史包。模块级`applies_when`定义该模块全部问题的适用范围，因此不是可任意patch的展示元数据：适用范围变化时，必须升major、退役该模块全部旧题ID，并为每个旧ID建立唯一的新ID后继；适用范围不变时，才能保留旧题ID。名称等不改变题义、适用范围或问卷选择的元数据修订可升patch，实际prompt hash仍须按题记录。24个核心构念保持冻结；要增加全公司适用题，新增通用扩展模块或明确标为不计入原核心分的补充题，不能悄悄改变“24题质量分”。若经济含义、评分锚点、适用对象或分部边界实质变化，创建新题ID/`rubric_version`并给旧题明确退役映射，不能让新答案覆盖旧ID；退役ID进入跨模块累计墓碑，永不重用。模块废弃只阻止未来新选用，历史manifest和观察永久可读；旧模块版本由发布包或历史manifest中的完整prompt/元数据解析，不能用当前catalog强行重算旧运行。新增事实题同样遵守稳定字段ID和作用层，但事实不进入评分。

新增模块必须附：投资问题与独有信息增量、适用与反例、1/5/10锚点或事实字段schema、分部/证券口径、与现有题的重复检查、触发证据、预计题数/成本、回退和最小正反测试。对同一经济机制不能通过改写问法重复计分；必要时复用已有构念或标`diagnostic_only`。杜邦、五力、恢复诊断默认按需使用且不计入质量均分。

事实题沿用同一套不可变ID、独立模块版本、归档hash和路由决策规则，但使用单独的`factrel_/factpkg_`发布锁：评分锁必须恰有24核心评分构念，事实更新不应改变评分包/方法ID。现有`questions/facts.json`的61题及旧导出保留可重现的1.0.0基线；新增`fact-catalog`只记录模块元数据和题目引用，不能复制第二份题文。未来新增事实字段归属一个事实模块，字段ID、问题ID、作用层、关系方向和prompt指纹逐项锁定。事实manifest同时绑定事实发布包与评分路由决策，X07发布集再绑定二者；不新建第二个LLM路由器。外部事实回答可省略`score`，内部规范化为`score=null`；任何数值分数均拒绝，不能因通用兼容层补5分。分部事实在缺`segment_id`时于派发前拒绝。

## 路由器：证据先行，允许交叉标签

路由输入是已核实的`entity_id`/证券映射、截止日、业务分部及最近路由快照；来源只保留URL、发布时间和短依据。先用确定性规则锁定身份、类型替代、明确的经营阶段和已有可信标签，再由StockQA用可验证搜索执行`ROUTE_01`补充有歧义的业务类别。LLM返回严格结构化候选、理由、反例、来源、置信度；skill的校验器只接受catalog已发布ID，并将候选映射为可重现的选择结果。模型分数只代表路由证据充分度，不进入公司投资分。

类型恰好一个、主生命周期恰好一个；行业可为0—2个重大经营驱动，经营/商业化前公司至少一个；周期、困境、跨境、客户集中等是正交属性，可与阶段同时存在。按收入、利润、资本占用和存续风险的实质性确定行业，不能只看公司名称、概念标签或股价。三个及以上重大业务、无法可信划分的集团，应拆分分部画像或转`full`并标覆盖缺口，不能静默舍弃第三个。高风险属性不得因quick模式预算被截断。`other`表示题库覆盖不足，不能当作精确行业。

每次选择保存`route_decision_id`、输入身份与as_of、路由器版本、模块ID/版本、每个模块的`selected|rejected|uncertain`及原因/来源/置信度、人工覆盖与到期时间。路由提示词提供模块的适用、排除与必要证据，不仅给ID和名称。人工覆盖须有操作者、理由和有效期；新公开事件、主营结构变化、覆盖到期或人工调整才重评路由。来源冲突/低置信度时仅运行可确定的通用题与必要风险题，行业和阶段结果标待核实，不伪造精确分类；路由失败不应导致整家公司从股票池消失。小幅证据波动不自动反复启停模块：相同标签须满足已定义的重要性/时间门槛，跨门槛或重大事件才切换，并记录转变原因。

S06的默认机器策略把“重大行业”作为快扫派发门槛，而非会计重要性结论：最近可靠年度/滚动期的收入、毛利或投入资本有一项占集团至少15%，即可进入候选；小于10%且连续两次年度披露、又无重大订单/资本开支或存续依赖证据，才退出原模块；10%—15%区间保留原选择并标复核。某业务占集团已承诺资本开支或有约束力订单至少20%，或虽规模小却对经营许可/供应/债务存续有明确关键影响，也进入待核候选。不同标签若描述同一收入机制，不重复选择模块。尚无收入的公司用有来源的主要开发项目和商业化计划选行业，不伪造百分比。缺披露/分母不可比时标`uncertain`，不用模型估数填门槛。阈值及例外写入不可变路由策略版本，用户可通过新策略版本改变它，但不能回填旧决策。

路由v2需绑定完整发布包、策略hash及能决定实际题面的冻结`profile_context`；其中包括业务/分部边界、周期位置、恢复触发、来源短索引和实际搜索执行回执。`policy/rejected`只表示列举的未请求可选模块，`unavailable/uncertain`可以无来源，客观`selected`必须有可信来源；不能为凑齐所有模块的拒绝理由而复制无关URL。历史快照按原策略可读，新派发须用可信当前UTC重新检查人工覆盖TTL，恰好到期即失效。已选困境与恢复模块时，DISTRESSED_01/02及RECOVERY_01—04作为受信任路由策略的必问题，与24核心共同计入派发最低题数，但不进入核心评分分母；预算不足在导出前拒绝并报告缺口。

S06应保留旧`validate_profile`的严格完整画像入口，另建以已验证发布包和路由决策为输入的部分问卷入口；不能为了支持模糊路由而让旧profile随意缺类型/主阶段。现存`cyclical`文件的`kind=stages`是题库历史分类，不代表它占用唯一主阶段名额；路由应将其当正交周期属性。旧模块尚缺机器化`activation`时使用纳入`router_version`的显式路由策略表，不能把文字`applies_when`或“无规则”当作自动选用。未请求的投资视角/诊断由策略依据明确拒绝，搜索不可用时可无来源地标`uncertain`；客观分类的`selected`仍需可核实来源。执行历史人工覆盖前按当前可信UTC时间重新检查TTL，不只检验快照创建时有效。决策内容hash还需封存周期位置、恢复触发理由、多业务覆盖缺口及路由搜索/模型回执引用，使实际问题文本和路由变化可重现。

## 拼装、预算与增量扫描

组合顺序固定：`common → types替代 → industries → stages → cyclical/overlays → diagnostics`。按发布锁文件逐模块解析，先执行现有替代和`critical`继承，再对已选模块递归展开完整`dependencies`闭包，按题ID/构念/作用层确定性去重；同ID不同题义、同一核心题被两个替代模块替换、选中集合内任一`conflicts`边（无论单边或双边声明）均fail closed。互斥备选可以同时存在于发布目录，只有共同被选入问卷时才冲突。缺依赖、依赖未决、图不闭合或依赖闭包成环时不产生半成品manifest/LLM任务。结果manifest记录有序模块版本与hash、路由决策ID、实际题ID/题义/渲染prompt hash、替代图、模式与预计题数。相同锁文件、profile和模式产生字节稳定的问卷；模块排列不能改变投资含义或任务键。

quick优先完成24个核心构念及不可延后的关键风险，之后按重大性派发行业/阶段/属性，诊断在明确未解问题时才发。超出用户配置的题数/金额/时间预算时，保留未派发待办及原因；不得悄悄删风险题、把未问题记5分，或绕过StockQA统一预算。full补余题。新增模块只为新适用公司生成新增题；旧题只在自身TTL、题义、经营事件或路由范围变化时重新问。路由变更导致退出的模块，其历史答案保留但不算当前有效覆盖；重新进入时先核对旧答案是否仍满足信息日期、题义、作用层和事件条件。缓存/任务键沿用C04与StockQA Q05/Q06：新增模块版本不能作为“重问所有题”的唯一原因。

## 分数与三维比较

核心质量、成长、估值仍以冻结构念/类型替代规则计算；行业、阶段和新投资范式题单列模块分与覆盖，不自动改变已验收核心总分。若将来需要新综合指数，必须另立`method_id`、权重、校准集和回测，不能悄悄把扩题加入旧分母。题义指纹只覆盖该题的定义、实际适用口径和渲染规则；新增无关行业不应改变所有题的方法标记，改变共有渲染规则也不能漏标为仍可比。比较两个时间点应先求相同实体/作用层/题义/期间/核心构念的交集；展示固定核心分和“同题篮”模块分，并披露题库新增、退役、缺失及覆盖差。不同模型的答案分别留实际模型/版本/搜索回执，不能将模型差异直接称作基本面变化。路由标签本身按快照沿时间轴展示，可解释为何某年新增半导体模块或退出成长阶段；跨阶段只对确已同口径的问题算分差，其余分段并排展示。

## 跨仓职责与UI

本仓拥有模块语义、静态路由校验和问卷拼装；StockQA接受冻结manifest派发已选题并存attempt/搜索/模型/预算回执；StockWiki是公司路由快照、观察、当前适用集及查询的唯一写入者。company-wiki继续可选关联身份，不存快扫副本、不要求下载财报。StockWiki首次导入已发布观察时应核对可信StockQA outbox的逐项ID/hash和S05归档语义；重放时还要对照自己已持久化的observation ID及逻辑执行键。同一执行键的新ID只能隔离冲突或按显式更正处理。历史legacy观察只读，不能让新导入删除模块绑定后降级接受；仅凭一条自包含JSON及其可重算hash，无法证明它就是先前已存的观察。发布集`X07`须绑定题库、路由器、StockQA、StockWiki的实际加载hash；不兼容时停止派发新题而保留历史可读。跨仓实现先核实各仓AGENTS与真实入口，写入须另获用户许可。

UI在企业详情显示本次选中的模块、触发理由、版本和覆盖；点开模块见题、分/未知、模型、信息日期及来源。历史页显示模块进出与同题篮对照，新增题明确标“新问题”，退出题标“历史不再适用”；人工覆盖和待核实分类可在维护页查看。列表仍按实体去重，提供行业/阶段/属性筛选；新增模块不自动改变旧白名单。界面只读StockWiki查询，不在浏览器另算路由/分数。

## 顺序与验收

评分链按`S04 → S05 → S06 → Q13 → W15 → U04`执行；事实题在`F01 → F06 → F02`接入同一发布规则，并连接既有W06/W11、Q06/Q07、W14、U02/U03、X07和G3/G6。先冻结模块兼容规则与路由决策schema，再实现本仓组合及反例，随后接执行器和权威库，最后做真实浏览器与小批次E2E。有关具体文件范围、依赖及固定正反例，以`docs/implementation/tasks.json`和`acceptance-cases.json`为准；任何任务的离线测试不替代真实搜索或跨仓E2E。
