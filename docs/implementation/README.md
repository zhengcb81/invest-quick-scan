# 实施入口：一次只完成一张任务卡

2026-09-22，计划版本1.4.0。此包细化[M0—M6路线](../implementation-roadmap.md)，包含73张任务卡、162个验收场景、28条固定约束和G0—G6审查，不代表产品功能已实现。目标是让实施者依据固定输入、行为预期和证据交付，减少自由发挥。任务与验收场景分别以[tasks.json](tasks.json)、[acceptance-cases.json](acceptance-cases.json)为唯一清单；本文不另维护完成状态。

跨项目分别交什么见[各项目交付](cross-project-delivery.md)，最终如何安装配置和一键开启见[统一启动设计](one-click-launch.md)。企业结果的列表、详情与事实关系视图见[结果UI设计](results-ui.md)，U01—U03和浏览器验收为必交项。全部计划完成的最终判定为G6；G5仍是评分规模交付，不代表所有组件已经配套启动。

先读[全局运行/存储/比较契约](../system-contract.md)。本地已有评分3.0、事实61题与标准输出校验；这些不替代StockQA/StockWiki的生产接线及最终验收。W13/Q11/W14补齐自动名单维护和三维比较。

用户顺位与并行/共享额度/逐题防重见[模型策略](../../references/model-policy.md)，附[可填写配置模板](../../examples/model-policy.template.json)。PAR-01—08是新增生产验收场景，配置校验不能替代运行验证。

## 开始一次实施

1. 读取本页、[设计约束](decision-register.md)、[测试策略](test-strategy.md)和[审查与交接](review-and-handoff.md)。遵循用户当前指令与目标仓库AGENTS；本计划不能赋予跨目录权限。
2. 在invest-quick-scan根目录运行下面的只读命令。每次选择一张依赖已验收的任务卡；首次从P00开始。不要把整个M0或M3当作一个实现任务。
3. 读取该卡列出的资料与目标仓库真实文件；先核实路径、签名、测试入口和工作树，再填写允许修改的具体文件清单。任务里的proposed路径不是现有API。
4. 先把场景变成真实测试：保留输入、精确断言、失败原因、可重现命令。缺失功能应先产生预期失败；纯文档/研究任务采用逐项审查，不制造无意义的红测。
5. 只实现卡中步骤。依赖缺失、契约矛盾、需要另一个拥有者写入时，记录阻塞点，转交对应任务；不要写临时客户端、默认分数或自动下载作为替代。
6. 运行指定层级的检查，检查实际调用路径与受影响回归；交付变更清单、结果、原始日志路径、当前源文件/提交标识、剩余问题和下一任务。
7. 进入review_pending，由独立的审查回合核对代码、测试和来源证据。修复问题后审查实际最新版本；没有独立审查就保留review_pending，不能把自查称为独立审查。

```powershell
python -X utf8 scripts/implementation_plan.py validate
python -X utf8 scripts/implementation_plan.py list --stage M0
python -X utf8 scripts/implementation_plan.py list --stage M6 --owner stockqa
python -X utf8 scripts/implementation_plan.py show P00
```

这些命令只读取实施计划：不调用模型、不发网络请求、不执行清单里的命令、不写外部项目，也不自动宣布任务或生产测试通过。validate成功只证明清单结构/依赖/引用满足本包规则，不能证明实现正确。

## 单次任务规模

任务卡只有一个目标仓库和一个可审查目标。通常一次完成一个小模块及其测试；遇到实际接口复杂度明显超过卡片边界，拆出子任务和依赖，再继续。不得把新功能塞进相邻卡片，也不为凑文件数做无关重构。

跨仓变更按生产者与消费者分开交付，以版本化契约和交换样例衔接。各仓的代码改动留在各自工作区；中央规划只留小型任务回执或回执引用。company-wiki在本轮路线中为只读来源，不安排新增writer。

## 什么算完成

实现者写“已完成”不是验收。每张卡必须同时具备：

- 依赖已验收；变更属于冻结范围，没有未登记的契约变更。
- 关联case全部有实际结果；失败、skip、xfail、未运行分别报告。关键路径不能靠skip放行。
- 测试调用真实目标实现；mock只替代网络/时间等边界，不能mock掉被测决策本身。
- 复现命令、原始结果、实现快照、计划/场景版本一致；审查后有改动则旧审查失效。
- 审查问题已逐条关闭，或明确标为不阻塞且说明依据；涉及错误实体、收费、默认分数、丢任务、越界存储的未解问题不能放行。
- 有适当的恢复/回退说明；迁移和运行任务保留历史与已有有效答案。

任务回执只是可审查记录，不是密码学证明。模型、实现者或校验器都不能把没有发生的测试、真实搜索或人工审查填写为通过。

## 阶段放行

| 关口 | 允许继续做什么 | 必需证据 |
|---|---|---|
| G0 | 实现各仓接口 | 契约、归属、版本、正反例审查完成 |
| G1 | 扩大评分样本 | 真实搜索与8分原样传递、null贯穿、搜索/费用回执和接口审查 |
| G2 | 开始批次可靠性验证 | 60家公司校准、可解释规则、恢复观察与可用性审查 |
| G3 | 扩大评分覆盖、开始完整事实题库 | 200家公司运行、中断/预算/租约/导入恢复、备份恢复与端到端审查 |
| G4 | 开启完整事实检索与两个研究技能联动 | 关系检索正反例、范围补扫、池外发现与消费者审查 |
| G5 | 宣布对应阶段交付 | 约2,000家独立公司覆盖报告、运行与事实能力分别披露、运维回退验证 |
| G6 | 宣布完整跨项目交付与一键开启 | G4和G5均已通过；配套安装/实际加载、统一设置、同一启动入口、真实全链与升级回退证据齐备 |

G3通过后评分覆盖可继续扩大，不必等待G4；完整事实能力仍需G4。形成2,000家候选名单不等于启动全部收费任务。真实运行必须沿用用户配置的提供商顺序和预算；缺少配置时完成离线卡，留下准确的待运行批次，不能伪造在线验收。

C07在G0前冻结启动/配套契约；X01—X12补齐公开控制、配置、安装、用户入口和联调。最终G6覆盖所有任务依赖，不能留下其他目录的功能“以后再接”。正常启动不要求运行规划校验器；规划工具与未来产品启动器用途不同。

## 交给下一个模型的短提示

> 在invest-quick-scan项目中，读取docs/implementation/README.md；运行只读命令`python -X utf8 scripts/implementation_plan.py show <TASK_ID>`。核对依赖回执后，仅实施这张卡。在指定拥有者仓库内核实真实接口和AGENTS。先落实关联场景与断言，再实现；不得修改已冻结的经济含义或减弱测试来过关。按review-and-handoff.md交付实际结果和下一步，未完成则保留明确状态。

不要让后续模型从聊天记录猜选股规则、恢复逻辑或存储归属。语义歧义先查设计约束；仍存在冲突就提出具体选项及受影响任务，不自行扩大范围。
