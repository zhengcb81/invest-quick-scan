# D1–D7 模块解耦整改

本轮从[原核查](report.md)的七组反例出发，保留原 StockQA 和 StockWiki 的事务边界，按下表核对原入口。验证使用自有临时目录和测试传输，测试账本、源文件副本和临时服务随测试清理。

| 项目 | 改动 | 应验证的行为 |
|---|---|---|
| D1 结果兼容 | IQS 消费稳定的搜索语义，供应商标识和回执扩展仍保留在原哈希中 | 新供应商与合法扩展可用于分类。篡改、主体不符和引用不符仍拒绝 |
| D2 服务并发 | 请求在短锁内捕获部署与共享组件，耗时操作在锁外完成。改配沿用活动检查 | 慢预览和启动期间可读取设置与结果。变更工作区不会把在途写操作移到新目标 |
| D3 页面启动 | 静态来源逐项加载，页面按实际依赖渲染，服务允许静态构建失败后启动 | 慢、缺失或坏的静态快照只影响依赖它的页面，正式接口仍可用 |
| D4 跨仓接口 | StockQA 提供公开策略校验，Company Lab 公开恢复与最终结果投影 | 既有策略兼容。IQS 使用原验证后视图和回执，原恢复不额外发模型 |
| D5 历史语义 | 发布版本选择对应渲染器，任务使用原发布资源 | 不影响提示词的源码改动可读旧题包，提示词篡改仍拒。新版资源可和旧任务并存 |
| D6 比较 | 默认问题分组消费题库的必答模块声明 | 新增必答模块自动进入比较，旧快照兼容 |
| D7 组件职责 | 准备、交付、批任务和执行器各自发布状态。StockQA 负责输入位置、工作和交付投影 | 增量注册复用当前执行器。封包字节、缓存引用、工作范围和已登记路径保持兼容 |

原规则继续约束主体、题义、预算、未知发送、历史回执和写入幂等。测试按改动边界选择，不增加运行门禁。

独立对抗审查复现了两个历史恢复边界。原发布目录可以独立于代码目录，恢复改用已登记原目录。原请求的语义提示也参与请求哈希，新检查点沿用既有载体保存该规则，旧检查点使用原版兼容路径。旧格式和新格式仍走原事件重放及回执校验。

UI 复审中，迟到的快照和初始连接都会使表单重新挂载。现在只刷新依赖该来源的页面或已有提示区域，设置草稿、名单理由和批量审阅日期保留在原控件中。坏必答声明在题库边界报告错误，缺少该字段的旧快照继续按历史规则展示。原服务可在静态构建运行中响应，静态请求按需等待，构建输出采用原子替换。

|---|---|
