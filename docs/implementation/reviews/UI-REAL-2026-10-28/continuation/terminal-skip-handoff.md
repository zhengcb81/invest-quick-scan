## Actual gap and fixed behavior

The previous within-pack known-invalid continuation did not cover original work that was already FAILED when a task resumed. `before_question` correctly refused a fresh claim; the engine then unconditionally set `work_claim_refused` and skipped all later pending questions. The new optional `assert_question_skip_terminal(question, handle)` is separate from the within-pack continuation proof. A refused claim first flushes preceding pending work. If that flush has any fatal stop, the new proof is never called and cannot clear it. Otherwise only a literal `True` proof allows the engine to retain an error/null result and original work ID, mark `original_terminal_work_skipped`, and move to later separately admitted pending questions. It does not call `after_question_failed` again, retry the failed question, or alter its score/status/attempts/fees. Generic/legacy/absent/non-True/error proofs retain the original stop.

The native assertion requires original strict C06 authority v2/3 and original owner/context readiness. It verifies the registered current selection and exact entity/question/scope/generation/work/identity/source bindings, FAILED state with no checkpoint or live lease, and latest response-available attempt. It reuses the original read-only `quick_scan_known_outcome_journal._physical` proof of original physical response, subject receipt, pack membership and settled/completed shared fee. The frozen subject matches the current context, every original shared member has its exact final response-available attempt and is FAILED without a checkpoint or has its original valid ready/delivered checkpoint, and same-owner/scope unresolved work blocks continuation. Unrelated companies are not a global lock. Original owner checks remain in force before and after; the next actual pack still performs all original owner/budget/lease guards.

There is deliberately **no call to `_owner_work`** in this assertion: that dispatch helper can call `recover_expired` on a different current projection. Only pure original `existing_work` selection reads and binding/anchor assertions are used. Old approved anchors retain the existing `ApprovedRefreshSession.assert_reactivated_original_binding` check. No Lease object is created or renewed by production skip code. Original FAILED reason is not guessed or relabeled; either a direct deterministic failure or an owner-closed known response can satisfy the proof.
