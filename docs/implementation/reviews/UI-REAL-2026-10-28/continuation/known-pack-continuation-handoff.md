## Behavior

The engine still stops by default. A provider-produced, structurally parsed pack (`complete` or `partial`) may continue to later independently admitted pending questions only after explicit missing/invalid/generator-rejected members have all completed their existing failure finalizers and an optional trusted lifecycle assertion returns literal `True`. Generic exceptions, finalizer exceptions, non-boolean/truthy callback results, absent callbacks, whole-parser `rejected`/foreign-identity/unparsed outcomes, unknown transport, and failed native proof retain stop behavior. Failed members remain errors with null scores; they are not retried, rewritten, or converted into successful batch completion.

The new native `assert_question_pack_terminal(handles, failures)` supports only the existing strict C06 v2/v3 authority and original v2 owner/context path. In a single read transaction it uses the existing pack journal `_read`, final-attempt/lease/work binding, durable original response verifier, failure event, checkpoint verifier, and physical budget terminal. It requires precisely the current physical pack membership, known completed 2xx native-search receipt, the one shared physical budget settled/completed with no in-flight fee, exact original failure reason/attempt/lease and no checkpoint, or successful sibling checkpoint/result-ready state. Same-owner/scope unresolved work blocks continuation. Unrelated companies' legitimate in-flight fees do not block it. The original owner/context assertion runs before returning positive; each later pack still passes its original owner, lease, scope, and budget admission before sending.

No new persistence schema, parallel ledger, task receipt, default field, default score, automatic repair request, price alteration, or model-side self-attested authority was introduced. The only prompt change is a final self-check against the supplied complete schema/example, specifically requiring `coverage` and `missing_fields` even for scored answers; there is no fixed numeric key-count runtime limit or unsupported vendor JSON-schema claim.
