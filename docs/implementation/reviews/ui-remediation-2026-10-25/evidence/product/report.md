## 检验

最终专属产品测试结果见 tests.xml 和 source-lock.json。原有 20 个 Node ESM/隔离 DOM/API 交互场景全部保留，新增 10 个涵盖字段保留、不自动启用/收费、唯一观测、同名实体/键盘、真实名字代码分页行选择、原字段题义与安全快照返回。Node harness 改由 stdin 输入，避免 Windows 32 KiB 参数限制；没有删旧场景。

测试是隔离 DOM/API fixture，不是生产付费扫描或浏览器视觉合规认证。真实 UI 浏览器和独立最终审查由总控统一做；没有自授验收通过。

## 保留边界

- 原 owner 没有合法准入/预算/完整部署仍必须阻断；表单不能生成这些权威对象。
- 真正历史只有一份、信息题无答案、结构化关系未提供时仍如实显示空/未知。
- 页面可选 provider 只引用后端原配置名；手填未登记引用最终由原 validator 拒绝。
- 没有源仓/全局临时文件创建、生产配置保存、数据库写入、收费 API、下载文件或 Git 提交。JUnit 与薄证据仅写本 IQS runs 目录。


## 独立审查整改收口

独审指出的实质反例均在原测试中补回归，先运行得到 4 个失败（review-red.xml），再根因修复：

1. 原交付 job 的真实完成状态为 completed，且 scopes 与 delivered_scopes 相等。现在推荐进入第 3 步看本次所选范围签收结果；明确不代表全公司全题或金融准入。process_exited 后残留的 launcher=running 不再冒充实际活动请求；unknown、partial、真正 running 仍优先。
2. 可选路径从空→X→清空和原本有值→清空，均删除精确键；不会保留隐藏旧路径，也不提交原 validator 不接受的空字符串，相邻未知字段保留。
3. 连接和模型策略两块在保存期间锁定整个编辑面，包括高级 JSON、输入、模型/额度行增删与排序。原先禁用控件状态在完成后恢复；即使模拟外部脚本在请求中改高级草稿，也只标本次提交已保存、当前草稿另有未保存更改，不会把 B 冒称 A 已存。
4. settings_changed、原连接实际 CAS 码 stale_setup 明确解释其他进程改动、保留草稿后重新读取核对，不自动重试覆盖；owner_policy_rejected 明确原策略未保存及需核对启用、原 provider/模型、额度组和原预算。保留原代码与诊断，不放松 validator。

最终原 20 场景和新增 10 场景共 30 项全部通过（12.09 秒）；证据与最终文件字节 SHA 见 tests.xml/source-lock.json。复核由独立审查 agent 完成；本分线不自行授予通过。
