# 进入 60 家阶段的范围说明（G1 交付物）

日期：2026-10-03。来源：G1 任务 deliverable（`tasks.json` G1 → “进入60家阶段的范围说明”）；配套审查记录见 [G1-review-2026-10-03.md](G1-review-2026-10-03.md)。对应任务：**L02（执行60家公司评分校准与规则稳定性评估，stage M2，owner=iqs，kind=live，cases LIVE-03/LIVE-04/REC-01/REC-02/REC-03/SC-11）**。

## 1. 本说明授权什么、不授权什么

**授权（G1 放行后范围）**：按下方协议准备并（在依赖齐备后）执行 60 家校准批次——目的只有一个：**校准先于扩容**（stock-pool-design §6），在扩到更大池之前验证分数稳定性、来源覆盖与规则可重现性。

**明确不授权**：
- 不授权 StockWiki 数据库/成员身份写入（216 导入仍等 owner 审阅 `reviews/universe-identity-preview-2026-10-02.json` 后单独给写授权）；60 家样本沿用 L01 的 `probe:<listing_key>` 探测内绑定，不产生 membership/paid Work。
- 不授权全池扫描（2,000 家）、不授权把校准结果用作生产白名单准入、不授权任何“先打分才能入池”的循环。
- 不授权新增数据采集渠道（行情、财报下载、公司文档原件、向量库）——轻资产边界（设计§2）原样适用。
- 不授权绕过 L02 的计划依赖：L02 deps = G1 + **W07 + W08 + W09**（StockWiki 侧，均未 verified）；依赖未齐前只做本说明内的离线准备（样本候选、冻结文件、协议脚本），不发付费请求。

## 2. 样本与重复设计（依据：设计§6 + LIVE-03 给定）

- **60 家分层抽样**，覆盖：三市场（A/H/美股，含北交所与否由配置显式声明）、主要经营类型、盈利/亏损、增长/成熟/周期/反转，并**必须包含多挂牌映射案例**。样本从 owner 已确认的 216 候选及其补充中分层抽取；候选不足时报告空缺，不凑数。
- **20 家重复样本**（LIVE-03）：同题同锚点重跑，度量分数波动与跨阈值迁移。
- **7/8/9 边界复问**：边界分重点重问，检查白名单阈值（`>8` 只收 9/10，`>=8` 收 8/9/10）两侧稳定性。
- **备用模型**与已固定锚点/规则一并纳入给定（LIVE-03）：换模型/换锚点/合并 question pack 一律先在同一校准集比较，**禁止隐形混分**（universe §4）。
- REC-01/02/03（恢复观察三分支）与 SC-11（同名指标不同经济口径不可比）随批评估，按 case 原文判定，不择优删样本（LIVE-04：只报共同成功子集、临时调分母 = 不放行）。

## 3. 执行协议（L01 已验证的纪律原样继承）

1. **先冻结后执行**：仿 `L01-pilot-freeze-2026-10-02.json`——样本清单、实体作用层、题面/锚点版本、提供商顺序、**请求/尝试/金额上限**、止损规则、回滚规则全部先落 `reviews/` 冻结文件并钉版入库。
2. **live 成本声明先行**：每批执行前声明调用数、量级、核验内容（项目既定 live 规则）；预算单位=问题级 primary requests，须显式区分 CLI invocations（L01 教训：11 调用≠11 请求）。
3. **顺序、有界、可续跑**：逐题持久化；达到上限即停派发并保存待办；unknown 属答案状态非执行异常；失败/unknown 原样保留，禁止删除重跑伪造成功率（LIVE-04/rollback）。
4. **真实搜索以厂商回执为准**：`search_status=executed` + `response_id` + HTTP 200 三要素，模型自述“已搜索”不计数（I17）。
5. **每题留痕**：model/rubric/比较组/原始分数/检查等级/信息日期/来源引用（见 §5 条件）。

## 4. 报告义务（L02 交付 + LIVE-03/04 判定）

- 按类型/模型分别报告：覆盖率、unknown 率、有效比较差异、入围（阈值）变化；分母=全部计划样本，**不择优删样本、不临时调分母**。
- 波动/跨阈值迁移矩阵、重大风险漏判、来源覆盖、缺失率；问题修订或通过建议（L02 deliverable）。
- 费用实录：请求/搜索/耗用逐回执；rate cards 仍为空则不编造单价，账单以提供商控制台为准。
- 检查等级诚实：本阶段产出停留在 `screening_checked`，不声称逐原文核验。

## 5. G1 发现绑定的进入条件（F1/F2）

- **F1（信息日期）**：L01 实测 20/20 答案 `information_as_of`/`published_date` 为 null，日期只在散文里。L02 二选一并在冻结文件中明示：
  a) 实现结构化信息日期采集（答案/来源层填真实事实期间，未知才 null）；或
  b) 正式接受本批全部 null→`not-fresh` 语义——分数仅供本次校准比较，**绝不因执行时间/导入时间显示为新鲜**，散文日期不得冒充结构化字段。
  两种选择都禁止用 `answered_at` 替代信息日期（universe §3.2）。
- **F2（来源元数据）**：回执现仅 URL。L02 冻结时决定：补采来源标题/发布日期（对齐设计§2 保存集）或显式接受 screening 级 URL-only 并在报告声明。
