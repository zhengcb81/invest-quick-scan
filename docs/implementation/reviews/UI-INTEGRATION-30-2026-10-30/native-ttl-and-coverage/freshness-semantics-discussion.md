# 仅讨论：24小时TTL与财务资料时点

**当前行为符合现有契约，不能直接认定实现bug。** 原规则明确取 `min(observed_at+TTL, information_as_of+TTL)`；因此今天认真研究、资料仍是8月的答案，按TTL24立即stale是这个保守策略的预期结果。它防止“重新导入旧事实就变新”，这一安全性应保留。本轮B仍按原规则验证，不调TTL、不改日期。

同时，这个策略对大股票池可能过度保守：许多稳态题的事实有效性、最新已披露财务期间与“今天核查过是否有新信息”是三个不同概念。用单一information_as_of同时承载它们，会把可靠但未有新公告的事实也不断重问。它是产品/语义设计的不足；是否还存在模型填错日期的问题，需要对照具体题义、原证据和日期定义，不能只凭日期旧就判断答案金融上错误。本次独立验收没有读取回答正文，因此不作这个金融判断。

未来可以讨论分离这些字段，而不是把任何日期重写成今天：

| 字段语义 | 记录什么 | 不能代表什么 |
|---|---|---|
| metric_period_start/end | 财报/经营指标所属期间 | 今天已重新核实 |
| evidence_published_at | 来源实际发布时间、cutoff内可获得性 | 指标必定仍适合今天使用 |
| information_as_of / fact_valid_as_of | 这条结论实际适用的时点 | 无证据支撑的“当前” |
| searched_at | 真实工具何时搜索、查询了什么 | 搜索完整、结果可信或事实未变化 |
| verified_at | 原生可信流程完成本题所需核查的时间与覆盖证据 | 模型自称核查、导入时间、任意续期按钮 |

对估值类结论，市场价格可能是30日、利润数据所属期间可能是6月、财报披露可能是8月；三个日期可以同时成立，但应明确分别记录，并证明截至30日使用的财务数据确为已披露最新可用数据。不能为了通过缓存测试，把8月来源直接标为30日。

建议未来按field配置有效期与再验证要求：行情/估值依赖市场日期与新价格；季度财务依赖原报告期间、发布日、是否有更新及相关事件；品牌/渠道/产业位置可以有更长但有限的复核周期。事件、身份/范围、题义或关键来源变化可以提前失效。缺必要日期、搜索失败或覆盖不足保持unknown/stale。具体期限需要按题义和实验结果设计，本次不提出任意数值或更改政策。

验证“查过仍无更新”也需要真实原搜索/工具回执、指定来源覆盖、cutoff内可获得性和明确成功状态；不是空搜索结果或LLM一句“没有变化”。保留轻资产原则：记录URL、来源时间、查询与覆盖的薄证据和hash，不下载保存整份公司文档。可复用已有工具、账本与证据接口，不新建执行器。

如果未来增加verification记录，应追加不可变记录并绑定原观察/field/subject/context/证据和policy版本，旧观察及日期不改。旧版本没有verified_at或核查回执时继续走当前保守规则，不从导入时间补造。迁移/新政策必须显式版本化，不能使历史结果突然“自动变新”。已完成CP的零HTTP恢复与研究资料的新鲜度是两回事；本次冷重启验收不能代替TTL有效性。

**本轮B的准确口径：** 新cutoff30只允许使用截至30日可取得的资料，不保证模型提供新事实。若真实答案information_as_of仍为8月，最多通过合法新cutoff准入、真实回答及入库链，**fresh/有效TTL复用仍未通过**。不能放宽规则、改日期或反复询问直到出现今天来宣称成功。应先判断本题需要的是当前市场证据、最新已披露历史指标还是重新核查的覆盖事实，再决定后续有证据的验证方式。
