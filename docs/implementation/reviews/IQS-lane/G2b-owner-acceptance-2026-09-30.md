From the IQS root, with StockWiki checked out at the commit above:

```powershell
python -B -X utf8 scripts/stockwiki_g2b_acceptance.py --stockwiki-root C:\Users\郑曾波\Projects\StockWiki --golden docs\implementation\contracts\goldens\stockwiki-g2b-72531b5-provisional.json --mapping-golden docs\implementation\contracts\goldens\stockwiki-mapping-72531b5-four-state.json
python -B -X utf8 -m pytest -p no:cacheprovider -q -o addopts= tests/test_stockwiki_mapping_contract.py tests/test_stockwiki_g2b_frozen_golden.py tests/test_identity_contract_cli.py --basetemp .tmp-g2b-frozen
```

The frozen [mapping bundle](../../contracts/goldens/stockwiki-mapping-72531b5-four-state.json) is 9,774 bytes; SHA-256 `da3991c0d85ef9a0bce7c9152475b9184942df74c34fab4c5c935fb0e375a96f`. It contains StockWiki public `build_identity_snapshot` output and public `build_mapping_result` DTOs for null/not-attempted, unknown, ambiguous, mapped, and source-mismatch states. IQS's independent `stockwiki_mapping_contract.py` validates version 1.0.0 shape, snapshot hash, exact query/as-of, candidate count/state, Security/Listing/Entity/source-binding joins, and the owner candidate projection. Five one-field DTO/query corruptions are rejected; a rehashed snapshot with a wrong source ticker is also rejected. The current StockWiki snapshot projects null listing validity dates, so this result checks as-of equality but does not establish historical interval behavior.

The coordinator script seeds two independent isolated roots **through StockWiki owner store APIs** using the exact deterministic fixture values in `tests/test_identity_g2b_export.py` and its offline ISO sample CSV. It calls public `python -m stockwiki.cli ... identity-export-g2b` twice, compares canonical bytes, and checks the public owner read projections for Entity/revision, active receipt, Listing/Security/source-binding joins, and registered MIC. It then calls IQS public `scripts/identity_contract_cli.py` with the exported bytes. It does not open StockWiki SQLite directly, use production data, make a network/API call, or write StockWiki.

Frozen [raw owner CLI golden](../../contracts/goldens/stockwiki-g2b-72531b5-provisional.json) is 2,765 UTF-8 bytes, without the CLI terminal newline. SHA-256: `0efc2c04daa7b6345078410a5df5ae0aa5bec9098b1523d7c25f9f60f53e5d2f`, matching StockWiki W04 closure. The first local capture attempt produced a different hash because it left Windows stdout `\r` after removing only `\n`; the script now removes the terminal CRLF before hashing, and the owner E2E fixture independently reproduces the exact expected hash. No mismatching golden was saved.

## Results and limits

- Two owner exports: byte identical and expected SHA. IQS CLI positive: exit 0, `status=valid`, no errors.
- Five one-field consumer negatives (Entity ID, missing owner receipt, source record ID, MIC registry membership, identity revision): each exits 2 with `semantic_validation_failed` and no company payload echo. StockWiki's own E2E separately covers 17 mutation cases; this coordinator run does not claim all 17 were independently repeated.
- Producer-side **duplicate exact Listing key** check uses synthetic labels “中微公司（合成标签）” and “中微半导体（合成标签）” on two distinct fixture Entities. Public snapshot/mapping APIs return `ambiguous` with two unmerged candidates and no selected Entity; an exact source namespace/record query maps only one Entity. Names are not used by this mapping API. This test does **not** cover a name-based resolver/import merge or establish the real-world relationship of those companies; SW-IDENT W02 retains that separate negative case.
- IQS frozen-golden, mapping DTO and CLI/plan suite after review repair: **104 passed / 63 subtests**. CLI suite includes duplicate JSON keys, >1 MiB input, unsupported package version, and Entity/AnalysisSubject contract fixtures. All coordinator temporary roots were removed; the pytest temp root was separately removed. StockWiki's pre-existing untracked `.claude/` was preserved.
- Independent review found an expired Listing could still map. Authorized StockWiki mapping source/test and IQS consumer fixes now apply `[valid_from, valid_to)`, reject retired/delisted records, and bind the query to the snapshot as-of. StockWiki focused mapping/snapshot tests: **33 passed**; full pytest stage: **655 passed, 15 skipped**. The full check script's Ruff cache write was sandbox-restricted; Ruff passed separately with its cache under IQS. The review found no remaining P0/P1 for this provisional interface slice; see the [review report](G2b-independent-review-2026-09-30.md).
- StockWiki's owner DTO mapping version is 1.0.0. IQS has an independent consumer validator and frozen owner-generated five-case bundle. Full G2b remains **partial**: no verified issuer receipt, multi-listing issuer bridge, public AnalysisSubject golden, production effective-date history, or public near-name resolver/import proof was supplied. W01–W03/scan eligibility remain separate pending tasks.
