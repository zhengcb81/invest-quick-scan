## 实际改动

- StockQA复用原SQLite的`quick_scan_research_visible_output`及原`record_response`事务，普通同步/异步受绑定扫描也持久保存公开最终正文。共享研究沿用同一journal；诊断开关只控制诊断，不再控制新结果的可恢复性。原响应、模型、费用及hash仍原样绑定，不另建数据库或客户端。
- 普通恢复优先原journal，兼容旧diagnostic记录；共用原题包标准成员解析，成员按独立事务保存。缺/坏题只留下该题缺口，有效成员可保存；已保存成员重复恢复复用原CP，不重复派发。
- Company按qid处理同一HTTP的回答集合。同值重复不反复应用，冲突只影响对应题，缺声明/缺题不再把正常题一起判无效。
- Company用同一`binding_findings`服务校验与自审。多期输入包含目标期时不能仅凭年份不同断言错误，只有错期来源的单期值仍受检查。时间检查不证明公式/数值正确。
- 预测按具体metric的basis和证据claim_kind处理，取消“计划：”句首口令；引用未来观察项不等于把它当已实现业绩。IQS也将预测期间和资料发布日期分别验证：forward期间可未来，资料日/来源发布日期仍不能晚于cutoff。
- 原冻结schema不改。兼容读投影放宽公开解释文字长度、事实items展示条数；事实多一条不丢整答。标识符、类型、实际冲突与其他结构边界保留。QA与IQS沿相同兼容规则读取，并用一致性测试避免独立部署适配漂移；没有让离线IQS新增必需的反向运行依赖。

## 使用与兼容边界

新公开响应保存和历史重放都沿原请求/receipt/主体绑定；恢复不能发送模型请求。旧没有保留正文的记录不能凭hash还原，不假造历史答案。私有思考/真实凭据不进入公开journal；传输原有资源上限仍有效。

整批partial表示仍有未完成题，不能据进程exit0宣称全公司完成；已收到的失败题不自动换模型或重问整包。未映射指标保持原文且不进标准聚合，真实冲突不冒充合格数据。

只做相关测试和本节点一次集中独立审查。原响应、旧schema、过去失败记录及已存在的金融问题都保留；本节点不把宽容读取称作金融准确性认证。
