# IQS UI 独立视觉与前端设计审查

日期：2026-10-25。角色：独立产品视觉 / 前端设计审查。审查对象：`http://127.0.0.1:8766/`，前端仓 `C:/Users/郑曾波/Projects/iqs-question-bank-ui-lab`，HEAD `cc382f3ddeab7de3f3f28bfb220078556a14d676`。本报告独立完成，未读取另一位用户流程审查者的结果。

## 判断

目前界面已经形成克制、可信的研究工具基底：系统字体、清楚的卡片边界、可展开原始记录、明确的数据缺口、不把未知算成低分，以及题目评分锚点的并列展示都值得保留。问题主要在“工程控制台的信息组织尚未变成研究者的工作流”，并非配色不够漂亮。最值得先处理的是配置编辑器实际不可读、题库键盘操作断链、响应式规则被覆盖、扫描页没有分阶段，以及结果长文本表格被元数据挤压。

不建议换框架、大改品牌、加动画、K线、渐变大屏或用绿色完成标记掩盖阻塞。应先把已有功能组织成少数清楚的阶段，分离研究内容与工程详情。

## 范围和方法

- 使用专属隐藏 IAB 审查 tab，只做导航、筛选、展开与键盘焦点检查。没有操作用户原有 tab，没有保存设置、维护名单、创建准入、启模、导入或收费调用。
- 实测视口为 **1280 × 720 CSS px**；DOM 实测顶栏高 **153.58 px**，约占屏幕高度 21.3%。截图是该实际视口，不能代表所有桌面尺寸。
- capability 列表仅提供 `pageAssets` / `webmcp`，没有正规 viewport resize 能力。因此 **没有实测手机、平板、1920宽屏、系统高对比度、200%缩放或屏幕阅读器**。小屏意见明确属于 CSS 静态发现，待后续真实视口验收。
- 深查：工作台、扫描任务、宁德时代结果列表和详情、题库总览 / common 详情 / IQS_01 抽屉、公司矩阵、设置、环境检查。抽查：宁德时代信息空态、历史模型对照、选股器、版本发布。名单维护和数据说明只检查导航与相关组件源码，没有执行维护表单。
- 结合已知源码做根因核对：`src/app/styles/app.css`、`ui/product.js`、`ui/product_core.js`、`ui/shell.js`、`ui/dom.js`、`ui/module_detail.js`、`ui/bank_overview.js`、`ui/companies_matrix.js`、`main.js`。没有跑全量测试或修改产品源码。

严重度：P1 = 明显阻碍关键操作或一类用户的访问；P2 = 影响效率、理解或长期维护；P3 = 可以后续优化。设计改进不等于后端金融资格缺陷。

## 逐项发现

### VD-01 · P1 · JSON 编辑器被压成一行

**证据**：设置截图 [settings.png](settings.png)。本地部署配置 textarea 实际高度 **35.998 px**，clientHeight 34 px，而字体行高 20.8 px，加上下 padding 后只能看到 `{` 一行。`product.js:470` 声明 rows=14，`:476` 声明 rows=18；`app.css:139` 对 input/select/textarea 一起设置 height:36px，`:36` 的 `.settings-editor` 没有重设高度，因此 rows 无效。

**影响**：即使所有后端校验正确，普通用户仍很难发现自己改的是哪个路径、预算或模型引用，保存前缺少可检查的配置全貌。这是实测布局缺陷，不只是“更喜欢大编辑器”。

**方案**：input/select 保持36px；textarea 使用 `height:auto; min-height:14rem; padding:12px; line-height:1.6`，高级 JSON 可纵向调整。部署常用字段提供有说明的表单；完整 JSON 默认折叠，保留专业用户出口。显示已修改但未保存提示，原 CAS 校验继续生效。

**验收**：1280×720 下编辑区至少看见10行；无手动拉伸也能读到多个配置键；键盘可从字段进入保存按钮；失败字段有定位，成功有已生效范围和下一步；不回显密钥、不自动启用策略。

### VD-02 · P1 · 抽屉缺少模态焦点管理

**证据**：[question-drawer.png](question-drawer.png)。点击 IQS_01 打开抽屉后，AX 焦点仍为网页根；下一次 Tab 直接进入被遮罩的背景“工作台”链接。`module_detail.js:106–147` 只有 role=dialog 和 aria-label，没有 aria-modal、初始焦点、焦点循环、背景 inert、Escape 和关闭后焦点返回。

**影响**：键盘用户会在抽屉看起来已打开时走进背景，可能离开当前题目；屏幕阅读器也难以判断交互范围。

**方案**：建立单一 Drawer/Dialog 基础组件。打开焦点到标题或关闭按钮；背景 inert；Tab / Shift+Tab 限制在弹层；Escape 关闭；关闭回到触发题目；保留 URL 深链。标题关联 aria-labelledby，弹层正文保留独立滚动。

**验收**：从题目入口用 Enter 打开，连按 Tab 不到背景导航；Escape 可关闭且回到原题目；直接打开带 q 的 URL 也有合理初始焦点；复制按钮有复制成功 / 失败反馈。

### VD-03 · P1 · 部分可点击内容不是可访问控件

**证据**：题库总览的模块卡片在 AX 中是普通 container，不是链接；`bank_overview.js:121–141` 为 article+onclick。题目表各行也只有 onclick（`module_detail.js:74–103`），题号是 code；矩阵模块标题 th+onclick（`companies_matrix.js:227`）。题库搜索和部分矩阵筛选在 AX 中没有稳定标签；placeholder 不能替代持久标签。已有产品表单 textField/aria-label 路径比这些旧页更完整。

**影响**：鼠标可以读题，键盘却没有入口；控件读出来缺少名称。改 CSS focus-visible 不能解决不可聚焦元素。

**方案**：模块标题用真实 `<a>`；题号用链接，允许整行辅助点击但不替代链接；矩阵表头用有名称的链接或按钮；搜索和筛选配 visible label；分段选择用 button+aria-pressed 或适当 tabs 语义。不要给每个普通容器随意加 tabindex。

**验收**：仅靠键盘从题库到任意模块、题目、抽屉再返回；可访问树中每个输入有名称，每个导航入口为 link，每个动作有 button 语义；当前导航设置 aria-current。

### VD-04 · P1 · 移动断点被后写的基础规则覆盖（静态确定，未实测手机）

**证据**：`app.css:47` 的 max-width700 媒体查询早于 `.topbar-inner` (:65)、`.page` (:71)、`.grid-3` (:82)、`.grid-2` (:83) 基础规则。相同 specificity 下后写基础规则覆盖媒体查询的 padding、grid-template-columns、nav gap 等。特别是 `.grid-2` 的 minmax430 和 `.grid-3` 的 minmax320 在窄容器仍保留最小宽。题库详情表直接放在 section 中，没有产品页共用 table-scroll 包裹（`module_detail.js:56–65`）。

**影响**：声明了“响应式”但实际规则没有完整生效，小屏和分栏窗口有页面级横向溢出的风险；题库长ID和八列表更易撑宽。

**方案**：基础规则在前，断点统一在后；grid 使用 `minmax(min(100%,320px),1fr)` 等可收缩定义；所有数据表统一局部滚动容器；页面内容 min-width:0。窄屏让筛选纵向排布、drawer近全宽、宽矩阵保留局部横滚，不强行把48列挤在手机。

**验收**：后续用正规375/768/1280视口实测，除明确的表格/矩阵容器之外 document 无横向溢出；主按钮、输入与关闭按钮在视口内；媒体查询的预期计算样式确实生效。本审查不冒充完成该动态验收。

### VD-05 · P2 · 顶层导航过平，且子页面失去选中定位

**证据**：[dashboard.png](dashboard.png)，12个平级入口，品牌、导航、状态分成多行，header高153.58px。`shell.js` 只用 route.path 精确等于顶层hash判断 active，进入 `/bank/m/common`、`/companies/e/...` 时所属主栏目不再高亮；截图中的题目抽屉背景可见这一点。

**影响**：每次看结果和读题都花约五分之一屏幕维持外壳；“生产结果”和“选股器”、“名单维护”和“公司矩阵”看上去是同等级同类数据，但实际来源不同。研究者需要先理解工程模块名。

**方案**：保留4–5个常用工作区：总览、扫描、公司研究、题库、设置；公司研究内包含结果、历史、信息，静态草稿 / 生产记录清楚分开。版本、矩阵、数据说明放相应二级页。可用紧凑顶栏+二级栏或窄侧栏，选方案由用户使用密度决定；不是必须用某一种审美。子路由按归属保持 active，补面包屑。工作区性质仍持续可见，压缩成一行状态。

**验收**：1280×720常用页面顶栏不超过约96px；子页面可一眼看出所属栏目；草稿和已存正式owner记录仍显著区分；每个历史URL兼容跳转。

### VD-06 · P1 · 扫描任务页把多个工作阶段堆在一条长页中

**证据**：[operations.png](operations.png) 和实际AX。依次存在准备组合题库、异步准备恢复、按公司批跑、异步入库、创建单扫描任务、手工导入、当前任务。未配置环境仍显示多组动作；相似的“预览”“开始”“刷新”分散出现。首屏主要是标题、两层提示条和工程缺项，真正的公司选择已在底部。

**影响**：有功能但找不到下一步，用户不知道应该用批跑、单包还是手工导入；空白部分越多，越像所有操作都不可用。

**方案**：清楚分成“1 准备公司与题库 → 2 扫描 → 3 交付查看”，顶部始终显示当前阶段、选中公司数、题数、运行条件、下一步。待处理任务为默认视图；高级单包/手工导入折叠到“高级恢复与迁移”。正常用户每一阶段只有一个主按钮。阶段状态来自原接口，不根据进程结束伪造扫描完成。

**验收**：新用户能在首屏回答“我在哪一步/缺什么/下一步点什么”；空 execution_bundles 时不出现假可执行主按钮；准备、扫描、入库各自有独立完成定义；恢复不重发已成功请求。

### VD-07 · P2 · 阻塞、未知和普通说明使用了近乎相同的蓝色提示条

**证据**：operations中“执行环境未配置”“题库预览可用但接线缺项 native_prepare_owner_dialect_not_supported...”均为蓝色；doctor中 blocked也是普通蓝条和英文表格值。`product.js:16` 的 note 只有 bad / info 两种快速入口，很多待处理状态直接调用默认info。结果详情7项缺口以英文代码长串呈现。

**影响**：用户看到了大量蓝条，却难以判断哪个阻止开扫，哪个只影响比较。直接显示原错误码有审计价值，但没有变成可执行的提示。

**方案**：统一状态组件：信息=蓝；需处理/证据不足=琥珀；明确失败=红；已核验完成=绿；未开始/不适用=中性。每条问题给“人话标题 + 影响 + 下一步”，原错误码可展开或复制；未知码保留原文，不猜解释。比如“当前准备接口不支持该准入版本；题库仍可预览；查看部署说明”。不能把 blocked 译成“服务异常”，因为这里很多是正常未配置。

**验收**：色彩和文字同时表达状态；阻断与非阻断分开；每个关键缺项有准确去向；原错误码、原资格和原证据可取回；不通过隐藏缺项制造可用假象。

### VD-08 · P2 · 长答案表格混排研究正文与机器元数据，可读性明显下降

**证据**：[result-answer-row.png](result-answer-row.png)。宁德时代只有一题，单行已高 **357px**；模型 `mimo-v2.6-pro` 被拆成多行，带微秒时间戳破碎换行，带64位十六进制摘要的发布ID占一大块。`product.js:52–64` 把题面、分数、模型、时间、版本/主体/发布、完整理由及证据同时放6列；`app.css:43` 对所有 product td 使用 overflow-wrap:anywhere。

**影响**：用户主要要读“什么问题、几分、为何”，现在需要穿过哈希和断裂的日期；36题后滚动成本会很高。保留完整元数据是对的，但不必全部占主表列宽。

**方案**：紧凑列表列为“题目/分数与状态/理由摘要/模型与日期”，行可展开完整理由、反证、来源、版本、主体、发布状态。长答案采用内容面板，不在窄表列里排整篇。时间默认 `2026-10-25 13:48 UTC`，保留精确原值在标题/详情；模型不拆词；ID默认前后缀+可复制全值，资格待复核仍在主行展示。摘要是显示折叠，不让LLM再改写原结论。

**验收**：1280px下模型和日期不在词中断行；默认行可快速扫读；一个动作可看完整理由和原始来源；36题原文不丢失；缺失主体、review_pending和不可比状态不被折叠到看不见。

### VD-09 · P2 · 公司矩阵的教学信息占据主要位置，图例和网格分离

**证据**：[company-matrix.png](company-matrix.png)，大量 basis / confidence / 历史口径解释在矩阵上方，网格本身需垂直滚动后才进入视野；48列英文竖排，小单元点阵需要频繁对照名称。源码已有按可视区域paint的虚拟化（`companies_matrix.js:245–253`），不应因视觉整改丢掉。

**影响**：矩阵更像契约说明页，研究者很难快速回答“哪些公司缺少哪些模块”。颜色不仅表示是否回答，这一差异容易在视觉浏览中被忽略。

**方案**：默认显示5项简短图例和“适用性，不是完成度”说明，完整依据释义折叠。保留左公司列固定，常用模块组切换并显示中文模块名；可选择少数模块观察，不默认要求读48列。将适用性 / 答案覆盖作为显著分段，表头对准；鼠标悬停和键盘焦点均能看完整标签。保留逐格真实依据与虚拟化。

**验收**：首屏出现筛选和网格；不用滚到顶部找图例；仅键盘可获取格状态与依据；适用不冒称已答；大名单滚动仍只渲染可视行。

### VD-10 · P2 · 路由切换缺少统一滚动与焦点策略

**证据**：在题目抽屉附近滚动后，点击公司矩阵落在说明下部和网格区域，而不是页面标题；`main.js:37–45` 全量替换root，仅fact深链特判scrollIntoView，没有普通路由的scroll/focus策略。抽屉开闭与普通跨页应采取不同规则。

**影响**：页面换了但当前位置看起来像随机停留，用户可能错过页面标题、数据来源或第一步。键盘和屏幕阅读器难以确定页面变动。

**方案**：跨栏目导航滚至主标题并聚焦可聚焦标题；详情返回列表可恢复原筛选与滚动；只改抽屉query时保留背景位置；明确深链anchor offset，避免stickyheader遮住定位标题。提供跳转主内容链接。

**验收**：列表→详情→返回保持工作上下文；跨主栏目回到内容起点；开/关抽屉不跳列表；后退前进不丢筛选；标题不会被stickyheader挡住。

### VD-11 · P2 · 无足够对照数据时仍显示重复的对照布局

**证据**：宁德时代历史仅1条实际记录、仅1个模型，左右模型默认都为mimo-v2.6-pro，同一完整长答案出现左右两列，下面“全部历史”第三次出现。页面没有说这是“同一条记录”，只是通用比较边界。

**影响**：增加垂直长度但没有比较信息，研究者容易误以为是两次独立询问互相支持。

**方案**：只有1条记录时先显示历史记录，提示“目前只有1条，暂无可对照记录”；仍可查看原记录。可比数据存在后才提供双栏选择；若显式选到同一观测，标记“同一条记录”。版本、主体、币种/口径等不一致仍按owner边界展示，不由前端推出差值。

**验收**：单条记录不默认伪造双对照；两个模型/两次观测可明确区分；每栏显示唯一观测时间和ID；不可比时不给数值差分。

### VD-12 · P2 · 需要小型组件边界，避免继续扩张单个产品文件

**证据**：`product.js` 当前约508行但很多为超长单行，涵盖结果、历史、信息、准备、批次、交付、任务、名单、部署、模型设置和doctor。各处自行组合状态文本、表格、JSON、异步刷新与按钮禁用。已有 generation guard、dispose轮询、safeEvidenceURL 和原owner权限检查是好的基础，不能在重构中绕开。

**影响**：目前视觉规则不一致与同页动作用语重复，正好对应多个局部render函数各自拼组件；后续加信息题工作流会进一步放大。

**方案**：渐进拆出 `StatusNotice`、`AsyncPanel`、`DataTable`、`EntityPicker`、`StageHeader`、`AnswerRecord`、`DiagnosticDetails`、`Drawer`，然后按 results / operations / universe / settings 拆页。保持原product_core纯函数、同源API、安全链接和服务端allowed_actions为权限来源；不为这次设计引入框架迁移。

**验收**：相同状态只在一个映射处定义；切页清理轮询、旧响应不覆盖新页、未知权限默认禁用；组件键盘与空态可单独测；整页行为保持既有公共API。

## 推荐的克制设计基线

这是可讨论的组件规范，不是未经实现就声称已有的设计系统：

| 范畴 | 建议规则 |
|---|---|
| 页面背景与表面 | 保持现有近白背景/白卡；边界#e2e5ea，阴影仅用于浮层；不要每个提示都套一层卡 |
| 主色 | 继续用现有蓝#2563eb，只给主动作、链接、当前导航；页面每阶段至多一个主按钮 |
| 正文 | 正文14px / 1.6；研究结论可15px / 1.7；辅助13px / 1.55；12px只用于次要元数据，不承担关键操作说明 |
| 标题 | h1 24/32，h2 18–20/28，h3 16/24；标题下先一句“能做什么/当前状态” |
| 间距 | 4/8/12/16/24/32的有限尺度；页面间距桌面24–32、小屏16；卡片16–24；连续内容避免重复大banner |
| 控件 | 主控件36–40px，触屏目标至少44px；textarea单独高度规则；label在上方，帮助文案在下方 |
| 状态 | 文本+颜色；已核验/成功绿，需处理琥珀，失败红，未知/未开始灰，普通说明蓝；每个原状态可展开原码 |
| 数据表 | 数字对齐、单位清楚；表头/关键列可sticky；仅表格局部横滚；研究正文不要被迫按ID的最小宽分列 |
| ID与时间 | 主要界面使用公司名+交易所/代码；内部唯一ID保留复制全值；日期清楚标UTC/信息截止；精确时间戳在详情 |
| 容器宽度 | 工具页可用现有1600上限；长阅读正文可从max-width:68–80ch起步，再实测中文断行和字号；不要让一段理由跨整屏 |
| 折叠策略 | 主结论/分数/待核实资格/当前阻断始终可见；完整JSON、协议哈希、历史口径说明默认折叠；不隐藏重大缺口 |
| 空态 | 区分未选择、暂无记录、能力未接入、读取失败、正在准备；分别给明确下一步，不能统一写“无数据” |
| 等待反馈 | 显示正在做的阶段、只读刷新时间、可安全离开/恢复说明；百分比只有原owner有可靠分母才显示 |
| 可访问性 | 原生链接/按钮/label优先；可见focus；aria-current/pressed；drawer焦点管理；普通表格保留表语义 |

现有常规正文配色从源码看主要为深灰和蓝，未发现足够证据认定其普遍对比度不合格。禁用元素低对比不应单独误报为WCAG文本失败。仍需对实际交互态做正式对比度、缩放及读屏检查，本轮未做合规认证。

## 落地批次

**可先做，一个UI可用性节点完成即可统一审查**：VD-01、02、03、04、10，解决真实布局/键盘/滚动问题；再做VD-06/07/08，形成“能看懂、知道下一步”的工作台。配小型组件测试与少量浏览器关键路径，不为每个像素改动增加一轮重审。

**可后做**：VD-05导航收拢、VD-09矩阵默认布局、VD-11对照降噪，与VD-12渐进组件拆分一起落地；不阻塞现有只读结果和题库使用。无需重新搭建一个新UI仓库。

建议一组UI验收场景覆盖：首次未配置、1家公司准备、准备失败/恢复、批次空态、实际1题结果、完整36题长内容、1条历史和多模型历史、61信息题空态、大名单矩阵、375/768/1280视口、键盘完整读题。收费调用不属于本轮视觉验收要求；真实长内容可从已批准的只读记录或明确标记的隔离fixture加载。
