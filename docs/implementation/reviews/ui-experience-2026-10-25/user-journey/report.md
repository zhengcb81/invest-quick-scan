# IQS UI 独立用户旅程审查

审查日期：2026-10-25。审查者：独立 agent `/root/ui_user_journey_audit`。对象：本机 `http://127.0.0.1:8766/` 已运行界面；依据当前总 README、公司工作台说明和产品接口文档。只读审查，没有修复产品源码、运行测试、启动模型/搜索、写名单、保存设置、准备/派发扫描或导入结果。

## 结论

当前界面已经能浏览完整题库、查看公司名单、检索正式结果，并展示分数、理由、来源、模型、信息截止日和实际观测时间；缺证据没有补成中间分，旧草稿也确实保留版本未知。这些是应保留的优点。

从研究员使用角度，它仍更接近工程操作台：首次开扫需要编辑多段 JSON 和理解原执行器对象，名单实际成员缺少可读公司名称，任务页有多套相互重叠的流程，数据说明残留与新产品事实冲突的旧表述。能查看数据不等于普通研究员已能独立完成“选择公司→配置预算→扫描→查结果”。本轮没有执行收费/写入路径，不能授予这些路径通过结论。

确认 10 项问题：P1 三项、P2 七项；未发现本轮已观察只读任务链中的 P0 问题。P1 是必须优先处理的产品可用性或信任问题，不代表已证明有越权派发或金融数据计算错误。

## 逐项发现与验收标准

### UX-01 · P1 · 数据说明与实际产品相互矛盾

- 类别：已复现的内容错误/误导风险。
- 路径：`#/data`；前端 `src/app/ui/data_notes.js:36`、`:100`、`:159`。
- 复现：打开数据说明，找到“当前接线与缺口”；它写“本界面当前读取历史 thin-scan 草稿，不是 StockWiki 实时库；生产 owner 封包和持续刷新尚未接入”。同一界面的生产结果已实际读到 CATL 正式观察。前面又写“构建与运行全程不向数据根写任何文件（…StockWiki/、StockQA/均只读）”，同时本页新段落和任务/名单/设置页面允许明确提交原 owner 写入。
- 用户影响：无法判断正式页是真是假、点击操作是否写入，削弱对安全与数据真实性的信任。顶部新增“静态快照边界”不足以消除后文“本界面/全程”的绝对表述。
- 建议：分别按“静态展示构建器”和“本地产品服务”说明读写边界；当前能力来自实际状态，旧快照缺口明确只限定于静态页。同步删改绝对只读/全站未接线声明。
- 验收：连接正式库时数据说明与工作台/正式详情一致；断开时显示真实不可用；静态构建只读和明确提交写操作的范围能一眼分清，不能出现互相否定的全站文案。
- 证据：`screenshots/data-contract-contradiction.png`。

### UX-02 · P1 · 实际名单成员没有人能读的公司名和代码

- 类别：已复现的核心操作可用性缺陷。
- 路径：`#/universe`→“实际成员与版本”；`src/app/ui/product.js:440`。
- 复现：点击“读取该名单”。公司列标题为“公司/实体”，实际每行是一个 UUID 链接，下方重复同一个 UUID；没有公司名、挂牌代码。整表 214 行，状态和长 source_sha256 理由占据其余宽度。
- 用户影响：看不出名单里有没有宁德、中微或某家美股，无法人工核对池内容；想移出公司时不能从所在行直接选择操作。唯一 ID 应继续作为底层身份，不能代替人类名称。
- 建议：在原 member 返回值上按精确 entity_id 联结原身份名称/代码（查不到则显示“名称未提供”并保留 ID）；名称/代码为主，ID 可折叠/复制；加本名单搜索、计数、分页和逐行选择变更。不能按名字猜身份或自动合并。
- 验收：认可 214 项中可按“宁德”或“300750”定位该实体；各行可见名称、市场代码、状态；ID 仍可取用，未知身份没有伪造名称；只读查看不触发身份或成员变更。
- 证据：`screenshots/universe-ids.png`。

### UX-03 · P1 · 首次开扫仍要求用户成为部署工程师

- 类别：产品化缺口，混合真实部署前置；不是原校验应该被移除。
- 路径：`#/settings`→连接配置/运行配置；`#/operations` 当前缺项。
- 复现：首次使用连接只能编辑整段 JSON；真实策略显示 `REPLACE_WITH_MODEL_A/B/C`。可调上/下移及并发，但模型/provider/额度组/预算不能用普通字段填写，页面要求到高级 JSON 配置；自动准备还需理解 admission_config、spend_authorization、agent.profile_sha256 等对象。扫描页因此无法继续。
- 用户影响：具备 API key 的研究员仍不能凭 UI 完成首次部署；很容易改错路径或原策略引用。README 能指导工程人员，不等同研究员自助工作流。
- 建议：普通模式给出逐步连接向导、已有原部署选择、模型/provider 下拉和显式预算表单；缺少原授权/部署应直说“需管理员完成此项”并列具体交付，而不是让用户编造原文件。高级 JSON 保留为专家选项。保存前展示变更、校验与新预算是否生效；不得自动开启收费或替用户定模型优先级。
- 验收：在已有合法原部署前提下，一位不写 JSON 的测试用户能连接、明确设置优先级/额度/预算、查看准备结果并走到可启动预览；空部署则明确列出必须由原 owner 提供的对象，不展示可启动假成功。收费提交仍需明确动作。
- 证据：`screenshots/settings-json.png`、`screenshots/operations-first-use.png`。

### UX-04 · P2 · 扫描任务没有随状态推进的主流程

- 类别：易用性/信息架构。
- 路径：`#/operations`、`#/doctor`。
- 复现：任务页从“组合题库与原owner登记”“异步准备与恢复”“持续批跑”“异步入库与原ACK”到旧“创建扫描任务”“扫描完成后：预览与交付结果”同时平铺。环境未就绪时仍有多种刷新/预览入口；阻断大段显示英文代码与配置路径。doctor 只说 StockQA blocked，没有直达修复该项的按钮。
- 用户影响：不清楚自己在“准备、扫描、交付”的哪一步；可能把 prepared/registered 当完成，或反复试不相关按钮。现有文字确实提醒这些不等同，但理解成本很高。
- 建议：用 4–5 步进度主线和当前唯一推荐动作，准备/任务/交付三类记录各有用户状态；旧预注册包与手动导入收进“高级/兼容方式”。默认显示中文问题、影响、下一步，原代码/JSON保留诊断展开。接续/放弃仍受原 allowed_actions 限制。
- 验收：空部署、有准备 job、运行中、暂停、状态未知、待交付、部分交付分别给出正确下一步；用户能指出“当前完成什么/还差什么/现在点什么”；未知态不能出现一键重发。
- 证据：`screenshots/operations-first-use.png`；准备/执行/恢复本轮未实际运行，以上状态验收是建议标准。

### UX-05 · P2 · 大名单公司选择和歧义提示不足

- 类别：易用性及身份选择风险。
- 路径：扫描准备、历史、信息、名单的公司下拉；`src/app/ui/product.js:169`。
- 复现：214家公司以原生长 select 选择，名称/代码后每项接完整 UUID；没有可输入名称/代码的站内检索。列表中还同时出现“中信建投证券股份有限公司 · 06066 · ENT_1af… ”和“中信建投证券股份有限公司 · 601066 · ENT_f007… ”，普通下拉未说明身份状态或为何分成不同实体。
- 用户影响：未来 2000 家更难选准；用户无法凭界面区分“同名不同法律主体”和“同公司跨市场身份待归一”的情况。这里仅确认存在同名不同实体，未核实它们应合并，不能擅自得出身份库错误结论。
- 建议：可搜索公司选择器，名称/市场代码为主、唯一 ID 作附属，显示 verified/provisional 和实体边界。对同名多实体给清晰歧义提示/原身份核对入口；由身份 owner 决定，不让前端按名称合并。
- 验收：输入中英文名/代码快速定位；键盘可完成；同名多个实体可明确区分并保持原 ID；跨市场不因 UI 选择重复启动同一个已归一实体。

### UX-06 · P2 · 评分筛选缺少题义标签

- 类别：易用性。
- 路径：正式结果“增加评分条件”、旧选股器“题目”；`product.js:123–143`。
- 复现：正式条件候选实测只有 `score.iqs_05`，输入 placeholder 为“原owner字段ID”；旧选股器下拉只列 IQS_01…24。使用者要自己去题库查题义。
- 用户影响：很难表达“竞争优势至少 8 分”；选错题号后条件仍合法，技术校验不会发现用户意图错误。
- 建议：显示“竞争优势可复制性 · IQS_05”及简短题面/版本/可用覆盖，提交仍映射原 field_id。字段候选继续由 owner coverage 决定，不给未采集题伪造覆盖；可提供“未有数据”状态的题库检索。行业/证券类型也应给真实可选值，而不是要求猜精确字符串。
- 验收：不记题号的用户能选择目标投资维度并看明白阈值方向；实际提交仍是正确原 field_id；缺失与不适用不变成通过。
- 已完成的正向证据：本轮 `score.iqs_05 >= 8` 返回 0 通过、1 不通过、213 待核实；此语义应保留。
- 截图：`screenshots/results-score-filter.png`。

### UX-07 · P2 · 只有一条历史却默认制造两栏相同对照

- 类别：易用性/比较任务质量。
- 路径：CATL `#/history?id=ENT_99ebb735-f072-41e4-8545-823bc012614f`；`product.js:180–194`。
- 复现：实际只有 1 条 mimo-v2.6-pro 观测。左右模型均默认同一模型，分数、时间和理由完整重复；下方“全部历史”又展示一次。
- 用户影响：版面很长，却没有形成任何对比；初学用户易把两栏误解为两次独立回答。现有上方“1条观测”能纠正细读者，但不应靠细读避免混淆。
- 建议：唯一观测时展示单条，并明确“还没有第二份可对照记录”；多记录时选择具体观测（模型+时间+版本），左右默认不同记录。不要推断可比性或自动算未经核实的分差。
- 验收：1条只显示1条；2条同模型不同时间能分别选左右；不同模型对照可看各自时间/版本/主体边界，同一 observation_id 不应被默认当作两份结果。
- 证据：`screenshots/history-same-record.png`。

### UX-08 · P2 · 查看详情后“返回”丢失筛选上下文

- 类别：已确认的导航设计缺陷。
- 路径：`#/results?query=宁德&…`→公司详情；`product.js:106`。
- 复现：搜索宁德进入其详情；“← 返回结果库”的链接固定为 `#/results`，没有原查询、条件、视图、页码或 snapshot token。查看多家公司时每次都需重做条件。
- 用户影响：在 2000 家筛选候选中逐一核读效率很低，且返回可能拿到变化后的新快照。浏览器后退可暂时绕过，但产品自己提供的返回链应保留上下文。
- 建议：携带安全的返回路由或保留本次筛选会话；快照过期按原机制要求刷新，不静默换一页。
- 验收：从第2页且有多个条件进入详情，再点页面返回，条件/视图/页码与同一有效快照仍在；从外部直达详情则正常退到默认列表。

### UX-09 · P2 · 旧选股器每个命中行塞进48条适用性说明

- 类别：信息密度/结果可读性。
- 路径：`#/screener`。
- 复现：添加一项 IQS_01 ≥ 7。每个公司“逐条件结果”仍显示全部 48 模块的适用性判断，多数是“？ 未评估”，真正当前条件命中行夹在其中；“命中题数”显示的是该公司已有评分数量（例如12），不是本次条件命中数1。
- 用户影响：只想比较7家候选，表格却变成大段纵向清单；标题还容易让人把所有已评分题数当当前筛选命中题数。
- 建议：主表只列当前所选条件的实际分数/状态、匹配结论；适用性与完整覆盖收进每行展开；将计数字段改成“已评分/适用必做题”或单列真实条件命中数。
- 验收：1项筛选时主行不默认出现48条模块；显示实际该题分数和是否满足；所有覆盖/未知信息仍可按需展开；不新增评分或自行加权。

### UX-10 · P2 · 首屏不能快速回答“214家公司到底扫了多少”

- 类别：数据覆盖与来源导航。
- 路径：工作台、公司矩阵、正式结果之间。
- 复现：首页显示214“名单快照”、12“历史静态运行”，缺少正式观察覆盖公司/题目数；公司矩阵标题没有“旧草稿”字样，且全局仍挂“当前结果工作区 isolated_research”横条，容易使用户将该页13/24旧评分和正式库1条新观察混为同一覆盖。静态详情有清楚的未绑定版本说明，正式页也有“静态草稿”入口，问题是全局首屏层级没有把两个来源先讲清。
- 用户影响：用户反复问项目何时能用，通常是因为不知道“名单存在、旧草稿、正式可用答案、金融审查”分别完成多少。
- 建议：工作台明确显示“当前原库：已有观察公司/有效评分题/待扫描/待审查”，并单列“历史草稿快照”入口；静态矩阵始终有显著来源和生成时间，不借用正式工作区标签。数据缺项时保持未知，不能为做进度条猜总数或金融资格。
- 验收：首次进入用户能在10秒内说明当前池214、正式观察仅覆盖已实际拥有的范围、多数尚未扫描、旧12运行是另一数据源；静态/正式双向跳转始终带来源标识。
- 证据：`screenshots/dashboard.png`，实际正式结果/矩阵读数见覆盖表。

## 不是本轮 UI 故障的前置与未验证项

- 本机自动准备配置为空、没有完整登记执行包、没有已启用快扫模型策略/新预算，属于真实部署状态。应提供更清楚的引导，但不能为隐藏阻断绕过原准入或自动收费。
- 原库目前没有可展示的信息题回答和结构化产业关系；“找AI硬件全部标的/供应商客户网络”还不能在该界面完成。应该显示能力状态及下一步，不能把空态当成已实现产业链检索，也不能从理由文字直接捏造关系。
- CATL仅有一条正式观察，无法本轮验证多模型、多时间真差异；表格能显示不代表这些比较任务已获数据质量结论。
- 没有执行任何准备/扫描/预算变更/任务暂停恢复/名单变更/导入/ACK动作。因此不作写入、幂等、并发、费用、错误恢复或全池端到端验收结论。
- 没有外网核对 CATL 数字或金融判断；本报告审查界面如何呈现证据，未评价那份回答的实际投资准确性。
