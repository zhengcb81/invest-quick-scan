# 各项目交付与联调顺序

2026-09-22。任务细节与依赖唯一来源为[tasks.json](tasks.json)。本页是按仓库划分的阅读索引，不维护第二份状态表。统一启动要求见[一键开启设计](one-click-launch.md)。

在本项目用`python -X utf8 scripts/implementation_plan.py list --owner stockwiki`提取某仓清单；owner可选iqs、stockqa、stockwiki、theme、industry。再用show TASK_ID读取单卡完整输入/预期。工具只读取计划，不改变目标目录或启动组件。

- **入口/现状**：`Projects/StockWiki`，现有console entry为`stockwiki.cli:main`；README已有doctor、UI与runtime。实际模块路径/测试命令由P00核实，不能假设采用src布局。
- **实现卡**：W01—W16、F03—F05、O01/O05；U01列表筛选、U02评分详情、U03事实/历史及完整浏览；X02跨进程桥接，X04首次设置，X05生命周期，X06按钮/快捷方式，X08安装配套，X09/X10离线与真实整体验收，X11升级回退。

- **接入方式**：不自行调用模型。runtime只管理快扫外层，不复制StockQA逐题重试；不调用正式研究scheduler或来源下载来完成快扫。
- **配置**：保存用户scan profile和组件位置/版本；模型配置保存其引用与版本，不保存第二份可变策略或密钥。
- **演进接入**：W16只能用固定、已安装且hash匹配的V17实现与当前StockWiki权威快照确定性重算影响范围；不接受调用方自签plan hash或本计划未定义的签名回执。在单一事务CAS完整输入和active ReleaseSet指针后，才按计划新增受影响字段generation/work。candidate仅预览，不产生生产任务、预算或POST；升级先按旧冻结receipt安全结算已授权请求，再检查新派发资格。W16唯一拥有一次性dispatch fence请求/回执schema；StockQA Q15先耐久写入`send_intent_prepared`，再调用W16 `consume_dispatch_permit`，由W16在owner事务内复核组件资格并原子消费permit、写入`dispatch_commit`。只有匹配的耐久commit回执授权一次POST；consume前崩溃/资格变化时POST为0且permit不可重放，commit后结果不明时只对账并禁止fallback/新attempt。X09固定双worker竞态、伪造plan和旧请求恢复案例。

结果页面规格与浏览器验收见[企业结果UI](results-ui.md)，不允许以CLI或启动状态页代替。

## company-wiki与其他深研模块

company-wiki只提供可用的既有身份/来源契约，本计划不安排新增快扫writer。其不可用不得触发自动下载或让所有轻量公司无法查询。revenue-forecast/invest-*继续消费经过其自身资格流程的研究线索，本计划不要求改其预测公式，也不把快扫启动变成全套深研运行。

自动准入W13、显式模型对照Q11、快照与比较W14按[全局契约](../system-contract.md)接线，不能将候选提名与正式成员、比较答案与主结论混为一谈。

## 安装和写入边界

“一个任务一个owner”指实现代码和权威状态的拥有者。安装器可在用户指定的部署目录协调已授权安装，但各组件迁移、配置、技能注册仍通过其公开安装接口/宿主机制执行；不能直接改另一仓的私有数据库或开发文件。代码依赖下载与公司资料采集分开，后者仍不属于快扫。

## 联调顺序

1. P00核实真实入口；C01—C07冻结业务、执行、查询、部署与启动契约，G0审查。
2. S/Q/W分别完成自己的生产与消费接口，按原G1—G3验证联网、评分、入库、恢复和预算。
3. F/T完成事实与两个消费技能，G4验收；O完成全池评分与维护，G5验收。
4. X01—X08把已验证组件组成可安装、可配置、可一键启动的组合；X07 release_set须绑定StockQA答案schema、parser、证据解释的真实加载release hash。可提前准备安装设计，但不得用未完成接口宣布可用。
5. X09用真实组件做离线故障联调；X11先验证配套升级回退，再由X10经同一入口做有限真实联网；X12整理交付，G6审查完整上线条件。

最终交付是一组配套版本、一个设置入口和一个日常启动入口；任何一仓“测试全绿”都不能单独宣布整个系统已经可一键开启。
