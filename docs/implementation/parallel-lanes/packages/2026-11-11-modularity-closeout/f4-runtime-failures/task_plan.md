# IQS 日常运行失败接入 F4

## 范围与入口

由 IQS 自己在正常 CLI、HTTP 和后台作业的失败出口保存原状态与脱敏原因，使用既有 feedback-observation/1。本计划处理 owner-cause-lost、business-failure-classified-expected 及同类普通失败。StockQA 负责逐题状态、支付事实和未发送恢复；跨仓只消费公开错误和引用。

|节点|实施和验收|
|---|---|
|A 已核实|基线 master 296ab842。复核中微 IQS_13/14 的原回执及原36题范围；以丢失原因的历史记录冻结边界。用八个已交接 RED、七个离线公开故障和既有五个 F4 正控对照。|
|B 已实现|统一原因、阶段、原 run/job/attempt 与 owner 引用。JSONL 先落盘再提交 .ready，由原状态根的 observations 输出。命令可指定单次 RESEARCH_FEEDBACK_OUT 或允许配置 RESEARCH_FEEDBACK_DIR。处理普通非零、已报告部分失败、进程突然丢失和失败回告本身写不出。|
|C 离线验收通过|从新进程读回正常失败、三题全失败、HTTP 500、原作业和真实强退的未确认状态。确认本地日志失败仍排完子进程输出、wait 一次、保持原退出状态，不能重复产生新的请求。与知识完整性、合法空结果和原生 F4 修复回告正控对照。总控对公开接口独审，在途扫描继续按既有版本运行。|
