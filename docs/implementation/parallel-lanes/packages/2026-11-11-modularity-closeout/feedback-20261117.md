## 共同接口

本仓从真实运行、单模块 E2E 或业务独审取得有效运行/attempt、原步骤、期望与实际，投影为独立的 UTF-8 JSONL。每行一条 `feedback-observation/1`。下例是离线偏差样本，接收后仍需归责。

```json
{"schema_version":"feedback-observation/1","owner":"invest-quick-scan","origin_owner":"invest-quick-scan","run_id":"fixture-run","attempt_id":"attempt-1","step_id":"project-result","check_id":"preserve-mixed-rubric-groups","expected":"groups-visible","actual":"group-lost","evidence_ref":"fixture-event-1","version":"fixture-v1","disposition":"deviation"}
```

必填字符串是 `schema_version, owner, run_id, attempt_id, step_id, check_id, expected, actual`，预期和实际使用稳定结果词。owner 指能修复问题的模块，origin_owner 是最初发现问题及最终回告的接收模块。可选字段为 `issue_key, evidence_ref, version, parent_step_id, details_ref, disposition, origin_owner`。disposition 可为 expected、deviation 或 unknown。原生作业、来源、日志及审查定位作为不透明引用，owner 在本仓解析。已确定的通用问题才给稳定 issue_key。相同错误文字或公司名不足以归并根因。一个运行的多条观测可关联同一问题。

业务协议与既有 stdout、stderr 维持原格式。事件按公开操作记录开始、结果、选择的路径、原因、实际版本及父步骤；原生日志已覆盖的部分通过引用读取。单独的反馈输出写入失败记追踪不完整，业务终态、计量和付费恢复仍由原责任层判定。单测/E2E 使用独占的短临时目录。密钥、认证头、整份原件、完整模型响应及生产库均不进入交接记录。成功明细轮转，开放问题仅固定最小脱敏复现材料；记录每轮新增磁盘量。

## 实施和公开重放

1. 用一次 scan 的原 job/attempt、冻结问卷版本、题号、已结算回执、result ID 和读视图关联阶段。区分未执行、供应商过滤/截断、完成但无法保存、真实完成；消费侧在反馈 sidecar 记核对，原始输出和收费记录使用现有归属。
2. 对同一公司/版本读取单尺度和混尺度公开结果，预先写明各组及题目引用。错误平均两个尺度、将 35/36 说成完整、遗漏失败题是业务偏差；各组分别展示、未登记或真实缺失是合法结果。发布缺失由发布 owner 负责，已有 DTO 在本仓投影丢组由本仓修。
3. 冻结两组拒绝合并的合成题目并打乱顺序，加一个单尺度合法对照。先用公共读取重现误投影，再改本仓 owner。对已收到终态回执的中断恢复，只读重组或重放，复核新付费调用数。问卷、实体和角色由 fixture 或配置给出。
4. 总控组合时由 IQS 输出同一 result/release，经 Dashboard 公开视图复验。记录实际逐题完成状态以及两个实际尺度，捕捉零退出但展示缺组的情况。真实公司问题沿现有工作树推进。

## 本仓 issue 与修复技能

建设 `repair-iqs-issue`，接收本仓已确认的 issue 或选择当前最影响主线的一项。利用已有问题卡/审查映射；无现成权威处置记录时，在本仓用一张小卡保留状态、各次 occurrence、影响、原生定位、根因、PWF 工项、回归用例、修复版本及发现方复验。先复现首个公开偏差，再在真正责任层修复、跑原错例和相似合法例。跨模块缺陷交给相应 owner；受理、处置和回告只交换受版本约束的公开结果。未查清、外部限制或未知费用分开记录。修复版本先记已修，原消费场景重放通过再结案；再次出现可关联历史并重开。
