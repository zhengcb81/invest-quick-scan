# 简版计划 v2（2026-10-18）

## 一句话

一组 24 题 × 一组已确认公司 → 带来源的草稿分数 → 一页对比。

## 明确不做（暂停）

- owner 准入 / route / admission / 预算预留 / 凭证绑定 / 观察入库
- retry decision、新 generation、旧题重答
- 外部包验收、看板扩张、状态快照等交付脚手架（已有产物保留，不再新增）
- 2000 家公司扩容

## 经济性怎么处理

不做预算审批。只做**性价比排序**：

1. 用实测的「单题成本 + 效果」给模型和搜索引擎排序；
2. 首选便宜且效果好的；失败或明显更差时，按排名回退；
3. 成本只记录、不设审批门槛。

当前首选（基于已有可用性）：

- 搜索：DeepSeek Search API（700 micros/次，成功才计费）
- 回答：MiMo v2.6 Pro

## 输入

- 问题：docs/implementation/questions-24.json
- 公司：现有已确认名单（先做宁德时代、飞亚达 000026、Alphabet）

## 输出

```
reviews/thin-scan-<date>/<company>/
  answers.json    # 24 条：status/score/summary/evidence[]
  index.html      # 一页看完
reviews/thin-scan-<date>/compare.html  # 跨公司对比
```

每条都是草稿：`draft=true`、`verified=false`，不构成正式结论或投资建议。

## 规则

1. 有分必须有来源；没有来源就标证据不足。
2. 来源必须是本次搜索真实返回的 URL；模型编造的 URL 直接丢弃。
3. 除同一题的 JSON 修复外，不做额外付费调用。
4. 模型返回非法 JSON：重试一次，仍失败则记证据不足。

薄草稿不再只读扁平的 24 题清单，新增两条入口：

1. 编排（先跑）：`python scripts/compose_company_bank.py --profile <profile.json> --mode quick|full --out-dir <dir> --module-package-id <pkg> --max-questions 40 --now-utc <UTC>`

   - operating/pre_revenue 没有行业模块时默认拒绝（除非显式 `--allow-coverage-gap`）。
2. 扫描（后跑）：`python scripts/thin_scan.py --company <name> --bank-manifest <dir>/manifest.json --out <dir>`
   - bank 模式逐题发送 manifest 的完整 prompt，并校验 prompt 与 `prompt_sha256` 一致；
   - 结果记录 bank identity、dispatch prompt hash、core/context 拆分；flat 模式明确标 `unversioned_flat_list`，不可当版本化结果。
3. 体检：`python scripts/bank_lint.py` 检查 catalog↔module 漂移、rubric 混版、type critical、artifact 一致性；当前 0 errors / 11 warnings。
