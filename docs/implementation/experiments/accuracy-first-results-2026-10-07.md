# 准确性优先：三市场小规模实验结论

2026-10-07，Phase96。结论适用于本批三公司和冻结输入，不关闭G3/F05，不改变生产模型顺位或逐题默认。操作规则见[实操手册](../../../references/accuracy-first-operations.md)，原始数值、评分与说明复核见[最小归档](artifacts/accuracy-first-2026-10-07/README.md)。

## 可以执行的结论

1. **先修证据，再有限复问。** 公司、期间、币种、单位、会计口径和表头齐全才算取证成功。搜索命中HKEX/SEC域名不等于命中正确公司；只有数字、没有年度表头，也不能支持精确答案。
2. **DeepSeek可作本批对照候选，用户顺位仍生效。** 增强证据下15个数值全对、14个引用支持；还有1个精确Capex缺证。更贵的MiMo Pro没有消除引用问题，MiniMax正确数值旁仍出现单位和年份错误。不能以数字字段准确代替全文准确。
3. **三题小包值得保留，30道判断题大包继续等待质量门。** 逐题与三题包同为15个数值全对、12个引用支持。三题包减少重复输入，参考token费较低，速度改善有限。本批不是30道评分题的生产验收。
4. **多模型一致只能发现不稳定，不能证明真值。** DeepSeek/MiniMax各答两次，15个数值四次一致，但只有12项四次均引用支持。相同证据缺口会产生相同猜测，平均分或多数票不能补证。
5. **高分入白名单必须审依据。** 本批发现模型承认缺资本回报/资本成本仍给7分，以及仅凭份额/规模给护城河8分。此类分数不能成为高置信筛选条件；保留原观察和缺口，条件性复核，不刷分。

## 设计和实测范围

样本为既有批准名单的宁德时代300750、中信建投H股06066、Alphabet GOOGL。每司5个官方数值参照+1个证据内无法确定的ROIC减WACC；另有护城河/资本回报两道真实题库问题的小对照。数值参照覆盖15项，正确拒答3项，判断题没有双盲人类gold。

四模型均开启思考：deepseek-flash、MiniMax-M3、mimo-v2.6-flash、mimo-v2.6-pro。不传temperature；解析最终content，独立reasoning字段在内存丢弃。请求/实际模型、UTC、实际参数、usage、prompt/证据/题义hash记录在账本；别名一致不证明后台revision不变。所有请求复用StockQA固定commit `6a9ff13864ebb160d5c4ab3cf2f42155d9f4aa99`的十个源码文件，不改三个在施工的外仓。

先比较Brave、Tavily、两者互补context、人工短事实卡和ZAI REST；再注册ZAI MCP、定向补搜及增强证据、重复、逐题/三题包和小评分对照。参照数字不给普通问题或检索query；人工事实卡是刻意含参照事实的正对照，不能算搜索成绩。增强输入合并已审旧查询缓存、新查询、人工筛选及4000字符临时摘要，CNCB问题也明确原始披露口径；因此不是单一搜索引擎的公平因果排名。

## 模型表现：增强证据首发

每模型三次请求，每公司六题，分母均为15个已知数值；失败块仍计入分母。引用支持是逐项来源人工审核，数值用十进制容差评估，说明另行独审。

|---|---:|---:|---:|---:|---:|
| DeepSeek | 15/15 | 14/15 | 3/3 | 65.187秒 | 34,841 / 13,567 |
| MiniMax-M3 | 15/15 | 12/15 | 3/3 | 76.334秒 | 33,928 / 6,470 |

M3首发CATL三项说明把billion yuan写成亿元，产生十倍矛盾；Alphabet EPS说明写入其他年份的basic EPS。其12项引用支持中至少4项说明不可信，最多8项通过本次所审四层检查。Flash也出现basic EPS年份错误。DeepSeek首发14项支持中未发现相同说明错误，但不能保证其他样本无错误。原答案不改，见semantic-review.json。

普通首轮互补context下DeepSeek为15数值/12支持，M3为14/12；补证后分别15/14与15/12。首轮Tavily的部分误差来自忠实复制摘要约数（如125.3 billion→125300 million），不能一律叫幻觉。只有精确数字和相关表头同时出现才满足本题精度。

DeepSeek再次回答15/13支持，M3再次15/12；四答均精确一致的15项中，仅12项四次全部引用支持。复问未解决缺表头、混合引用和说明错误。适用做法是先定位缺口补证，再在同一冻结口径/证据下让第二模型独立回答，不把首答或预期分数告诉它。

缓存分三层：检索缓存、供应商prompt缓存、答案检查点。本批warm核验45个首轮探针、53事实+4评分探针，HTTP0、key读取0、账本hash不变；探针数不等于唯一缓存数。此结果只证明实验缓存，不代表生产三层均已接线。输入包共享证据仍会重复消耗prompt token，缓存价用实际hit计量。

## 搜索与ZAI诊断

外部搜索返回短片段作为带ID的不可信context，回答模型不再次调用原生搜索。本轮未保存财报或网页正文；官方PDF只作在线参照/搜索索引来源，未下载到本机。

同一ZAI_API_KEY：REST `api.z.ai/api/paas/v4/web_search`返回HTTP429/error1113“Insufficient balance or no resource package”；MCP `api.z.ai/api/mcp/web_search_prime/mcp`初始化/列工具/`web_search_prime`调用成功。因此是REST权益桶拒绝，不能推成密钥失效或MCP整体被封，也不能按普通频率429盲重试。参见[官方REST指南](https://docs.z.ai/guides/tools/web-search)和[官方搜索MCP](https://docs.z.ai/devpack/mcp/search-mcp-server)。

MCP本批九个公司检索query均HTTP成功，但只有宁德时代毛利率1/15精确事实有支持，其他结果存在错公司、域名级链接或缺期间/表头。四个模型均只回答1项且有支持，说明主要是context覆盖不足；不能把“已答准确100%”当完整检索能力。MCP可保留为补充搜索路由，本批不支持它独立承担精确财务取证。Brave/Tavily互补也需主体过滤、表头/单位保留；源按URL去重、同URL的互补片段按内容hash保留。
