## 金融质量：人审结论与机器接口缺陷分开

三位独立评员各看36匿名槽，先于费用/策略解盲。初判108槽为47部分覆盖、8审慎不足、53缺答/遮蔽，整题充分覆盖0。审慎承认不足不算充分正确，部分覆盖也不等于整份答案错误。

人审发现了OCF/营运资本定义混用、合并收入扩大成广告收入、净债务算式与结果矛盾、由单年现金推成多年表现，以及由增长/规模推成留存或复制壁垒等问题。30个重大或争议槽再由另一位fresh评员先独立落盘，再看初判：21确认、3修订、6保留争议；原始双方判断均保留。30槽是按疑点选出的，不能外推总体错误率；不同评员择取命题也不能相加成为准确率分母，更不能以多数票造真值。1—10判断没有唯一评分gold。

原JUDGE导入108初判、原CACHE解盲已真实成功。另暴露本轮评测接缝：38个结构化数值命题在原scorer全部不可评，其中35个使用`value`而原API读取`value_decimal`，另3个维度不全。只把已有数值精确投影为`value_decimal`的第二次重放仍0匹配：期间/币种或完整会计定义未形成唯一reference身份。没有补reference ID、改语义或用答案值倒找gold。两个真实结果均保留，**不能把0匹配算0分或100%准确**。

原API另用明确标为合成的契约探针确认：精确参考值可识别，保持维度的错误值可判矛盾，真实缺维度仍不可评；探针不进入真实样本或10个预锁标量的分母。后续收费实验前，必须让真实评审schema产物通过同一个scorer正反例，不能仅验证每边自己的schema。

二审冻结文件曾把raw SHA与canonical fingerprint比较，留有`bundle_fingerprint_match=false`。后处理已用原JUDGE canonical API单独复核实际指纹匹配；原文件/原标签不改，保留最初“全部验证通过”表述过宽的更正。此类机械问题不能混报成模型错误。

## 缓存能说明什么

完整usage子集里，DeepSeek逐题缓存比例98.1951%、三题包97.6770%；失败的第二次公司agent仍有98.6208%。MiMo第一次公司agent实际0%，第二次78.2253%。因此缓存命中不保证交卷或金融正确，也没有证明公司agent必然比其他组织方式更省。

比例分子是该子集cached input tokens，分母是同子集全部input tokens；MiMo三题包第二次只覆盖3/4回执，73.4792%不能外推全会话。不同顺序可能共享已热前缀，本次没有独立冷/热随机对照，不能把差异归因于策略。自建答案缓存、共享沙盒与供应商prompt缓存是三件事。
