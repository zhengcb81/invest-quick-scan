# 公司agent与问题发包：实操设计及实验边界

2026-10-16。本文区分工程机制与尚待实测的效果，不代替[T4登记](real-contrast-t4-registration-2026-10-16.md)及[独立质量评审协议](real-contrast-t4-analysis-protocol-2026-10-16.md)。本轮金融结果尚未评审，不能把以下候选结构称为已证明的最优方案。

## 优化目标

优化单位是“一家公司完成一轮可追溯快扫”，首先减少实质错误和无证据高分，同时保留充分覆盖、审慎不足与缺答三个不同结果。全部unknown不算高准确率；多引用、模型一致、JSON合法、少HTTP或高缓存比例也都不能单独代替这个目标。通过质量门的方案才比较整公司真实费用和耗时。

公司agent适合负责取证计划、选择相关问题、识别缺口与有界修复。它的名称不意味着一次HTTP，也不意味着自动缓存。若每轮重复长推理、重复搜索或携带越来越多无关历史，费用与速度可能更差。问题数量、实际SDK轮数、供应商HTTP、逻辑搜索、搜索协议控制请求分别记录。

## 推荐的职责分层

| 职责 | 现有工具与边界 | 不能交给模型自行改变的内容 |
|---|---|---|
| 任务身份与范围 | StockWiki真实身份、冻结题目/模块版本、信息截止与会计口径 | 实体/挂牌归并、原题ID和锚点、期间及单位 |
| 证据需求与补证 | EVID逐题缺口/有界查询计划；原StockQA搜索provider及同账本 | 无限搜索、伪造日期/来源、把摘要当审定事实 |
| 公司共享上下文 | SESSION公司累计额度/短会话、不可变证据版本与每题检查点 | 每个小题重新发一份公司总额度、丢失未知请求后重问 |
| 选题与作答 | LLM在明确剩余题ID中取证/选择小包，保持思考开启 | 删题、改评分含义、私下使用截止日以后的材料 |
| 标准化输出 | CODEC确定性展开紧凑答案，原standard_answers/AnswerSink验证 | 默认填5、猜公司ID、丢失冲突、从一篇报告臆测拆题 |
| 诊断与二次复核 | CLAIM口径/引用诊断及匿名critic输入；不同模型有界修订 | 用规则无告警或自我确认充当金融验收 |
| 质量与经济性 | JUDGE独立匿名逐题评审，之后CACHE读取真实回执 | 先看价格挑好样本、删失败、猜费用或用缓存率代替准确性 |
| 留档与消费 | 原存储owner追加公司×时间×模型观察，UI及下游读取版本化结果 | 另建公司身份主库、覆盖历史分数、提前关闭生产联合门 |

这里不再造LLM客户端、搜索客户端、价格账本或另一套业务校验器。研究控制器只接原公开入口；实验不是正式评分入库授权。

## 问题包应按证据依赖组织

先以同实体、同期间、同分部/合并口径和共享证据聚合问题，再看输出空间及模型实测结果决定每包规模。固定三题是本轮可比较的处理组，不是全行业定律。经营事实抽取、会计推导和竞争判断可以共享资料，但需要分别保留原问题ID、锚点、原子结论、引用及不足字段。

给公司agent全套问题时，仍由控制器保存完整剩余题集合和累计上限。允许agent安排处理顺序；不能让它自行宣布某题不重要后消失。提交以紧凑、明确字段为单位，确定性补上公司/截止/上下文指纹等元数据；无效提交只回安全错误位置，不保存隐藏思考或无效正文。修复进展、已完成题与失败分开记录。

逐题可能减少混淆，但重复推理多；三题包可能摊薄成本，也可能遗漏细节；持久公司agent可能复用上下文，也可能积累错误。三者必须用相同题义、证据、预算和全分母比较，不能靠名称判断。报告真实每次响应提交题数，不能仅用“打包”标签推断实际批量。

## 缓存有三种，分别核算

检索缓存复用已结算、有资格保留且仍有效的短证据；供应商prompt缓存是否命中取实际usage；答案/检查点缓存避免对匹配题义、证据、期间和模型版本的已完成项反复提问。它们不是同一个机制，也没有跨供应商共享prompt缓存的承诺。

稳定前缀宜按“通用契约/工具与固定格式→共同评分规则→模块/题义→公司证据→当前剩余题与反馈”组织。可变运行ID、当前时间、请求顺位等放到动态上下文，避免无意义破坏公共前缀。同公司证据使用稳定排序和source/fact ID；短事实用同一版本复用，不反复拼整页网页。

跨公司复用的是公共规则前缀，不能把上一家公司事实带给下一家；跨模型复用的是同一事实包，实际厂商缓存分别统计。保留必要的私有工具轮历史由原SDK完成，隐藏思考不写入文件，其他公司/模型也不能继承它。

缓存比例上升仍可能伴随总输入、思考输出和总费用增加。最终同时看绝对token、output包含思考、真实请求数、整公司墙钟和已知/未知费用。思考token是output子集，不能再加一次；SDK读取超时/会话准入时限不是严格总CLI完成墙钟。

MiMo当前[官方思考协议](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/deep-thinking)还说明：思考下temperature/top_p采用其推荐值，max_completion_tokens同时限制思考与最终答案，多轮工具历史须私下完整回传reasoning_content。因此跨供应商即使请求相同temperature，也不能宣称实际采样温度受控；修复长思考不能靠删工具历史或擅造未准入的reasoning_effort参数。原SDK继续私下保留历史，持久结果只收最终答案和用量。

## 复核优先解决什么

先核身份/口径/引用和证据缺口，再决定复核。8分以上且将影响白名单的关键项、财务真实性/生存、重大反转条件、模型结论冲突适合有预算的独立检查。两模型读同一份不足证据可能一致地过度乐观；先补证再复问通常更有信息价值，但该效果也要单独实测。

交叉critic只能提出有限修订或诚实不足，必须保留before、增量和逐题来源。相同事实不支持的高分被改为不足，可以减少错误风险，却没有增加已知业务信息；两项收益不能混为一谈。反之，补了答案但引入新错应如实记回退。暂时低谷、周期重启和耐久优势的观察标记继续保留，不能把当前差指标自动等同永久淘汰。

## 当前实验如何回答这些问题

T4首先固定Alphabet同一18事实/9来源/12题，比较两模型×三策略×两重复，独立盲评后才比较经济性。这一阶段隔离发包和会话机制，不声称测试了自由联网agent的全部能力。随后四个预选格用另一模型对同证据做有限critic，检验纠错与回退。

新增搜索属于下一独立处理组：事前固定问题、公司、截止、搜索预算和来源处理规则；分别观察原证据、按缺口预取证据、agent有界主动取证。若比较Brave/Tavily，须分别登记一次intent，不能把首成功即停止的fallback列表当A/B。每份新增证据独立hash，检索及模型费用都计入；没有合格证据的空结果也保留。搜索短摘录作为不可信数据context传给模型，不进入system指令区，不下载公司正文/财报。

原native研究搜索schema21候选已完成隔离回归，但只能在schema20的T4及critic均终态后另登记部署；真实路由还需实际准入及已核权利。公开价、可用API key和有存储/评测权利是不同证据，不能硬填资格。此处是待执行设计，不是已实现或已测胜出的结论。

最终[实操手册](../../../references/accuracy-first-operations.md)只吸收真实结果支持的默认方法和适用范围：允许保留“不足以自动评分/没有质量赢家”的结论，不为了给出推荐而强行推广到2000家公司或所有行业。
