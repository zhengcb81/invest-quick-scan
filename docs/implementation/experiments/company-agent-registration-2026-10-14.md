# 公司agent比较实验：预注册 v1

状态：设计冻结；执行器、真实证据输入与最终评分参考尚待接收。**尚未发出本轮模型或搜索请求，不能引用本文件为实验结果。** 本方案承接B01，不修改原试点账本、名单或题库。设计依据见[架构判断](company-agent-design-2026-10-14.md)，机器配置见[registration.json](company-agent-registration-2026-10-14.json)。

## 1. 假设与实验臂

H1：公司级自主研究能提高有依据的正确覆盖，而不只是补齐JSON。H2：共享证据、依赖分包和定点修复能以更少重复工作达到同等或更高质量。H3：稳定前缀会提高供应商可观测缓存收益，但不一定减少总成本。

|ID|处理方式|固定不变的边界|
|---|---|---|
|A fixed3|按原题ID每3题一包；共享公司证据；同等有限补证/修复|4个初答包；软件指出缺口后最多2轮修复；不是故意削弱的逐题基线|
|B free_agent|一开始拿12题，自由选择搜索、分组、顺序、自审与补充|有界工具与资源，最终仍逐题原schema；不能读gold|
|C evidence_agent|证据表→证据依赖图→3–5题小包→缺口驱动补搜/定点补丁|同一初始证据与工具；所有计划和检查请求也计费|

三臂都开启思考；同模型主比较固定实际端点/模型/参数、资源上限、截止日、题目原文和锚点。都允许软件确定性检查与有限自审。独立第二模型复核是后续消融，不能只给C免费评委。逐题及一次全套单调用作为诊断控制，不与主矩阵一起无限展开；“一次全套调用”不等于有工具循环的公司agent。

## 2. 样本、问题和评审资格

S1/S2资料截止固定为2026-10-13（UTC当日结束；公开时间必须早于2026-10-14T00:00:00Z）；访问时间另记。来源仅有日期且无法确认边界时保留不确定，不能以访问日期伪装公开日期。S3若换截止日，先登记新revision。

开发集沿用宁德时代300750、中信建投H股06066、Alphabet GOOGL；它们不是新选股票。实际issuer ID与scope必须来自StockWiki真实接口，ticker仅供人识别。多地上市不复制公司，A/H不同口径或share class仍须明确。

每公司第一阶段12道现有通用题，ID固定：IQS_01、02、04、05、06、07、10、11、12、16、18、20。覆盖需求、续存、行业、优势、趋势、管理兑现、资本回报、现金、披露、偿债、替代风险、增长兑现。完整原题对象（含锚点/适用条件）以本卡targets及文件hash为准，不重新写题。扩展先沿三公司原manifest的固定30题基准（已有行业/生命周期模块选择），不把它称为所有适用模块的完整全集；真正全适用题集另按公开路由冻结。旧manifest不是新实验的owner批准。

独立评测人员在研究执行前冻结：主体/范围、资料截止、可回答性、关键事实/单位/期间、来源定位、评分可辩护区间与不足项。评分区间没有可信依据就标not_reviewed，不造精确分数gold。原FIN的90个null继续保留；软件测试通过不增加金融资格。

旧15个数值+3个证据内不足探针只作开发校准，必须独立重核来源。探针不计入36道评分题准确率；“已知不足”只适用于冻结证据实验，开放搜索后若找到充分新证据，不能仍强迫拒答。研究进程只收到问题，不收到expected_value/tolerance/评分区间。参考文件不放在agent可读沙盒；tools不提供任意文件读取，评测进程另载参考。

三个旧公司被反复调参，不能当留出集。确认阶段从用户已批准名单里确定性抽取6家未用于调参公司（三市场各2家），冻结选择依据后再请求；若没有可用名单/实际身份，不替用户编新公司。没有6家合格参考则报告可用样本及不足，不强凑。同一公司重复运行不是新独立样本。

## 3. 分阶段执行，避免因子爆炸

**S0 工程预检及接口资格。** 候选执行器先离线测试。总控通过现有StockQA入口对实际路线探针：thinking开启、多轮tool回传、最终content/finish_reason、缓存usage、限额错误分类。每模型最多6个物理请求，最多4模型24个，包含第5节至少3次稳定前缀及一次变动前缀对照；其余用于思考/tool多轮资格。若不能在6次内兼顾，先修订矩阵并留痕，不暗增318总上限。未验证的参数不猜填。多轮缺协议字段、reasoning泄露或无法记录实际请求，先修对应接口，不静默关思考。

**S1 同证据实验。** DeepSeek-flash作固定研究对照（不改生产顺位），3公司×3臂×2次=18个公司会话，每会话最多8个模型HTTP，搜索0。每公司相同冻结短证据可用；各策略可自主挑相关子集，token差异记为处理效果。初始证据板构建成本单列并给每臂分摊同等份额，不把人工加工当免费生产能力。每公司两轮用预先冻结的轮转顺序ABC/BCA/CAB及反序，不能看结果选最好的一次。

**S2 真实检索实验。** 同3公司×3臂×1次=9会话，仍同主模型，Brave外部检索为第一固定路线；每会话最多10模型HTTP/10次查询/15分钟，所有臂工具权限及短片段总上限相同。A也允许按缺口补证，B/C的研究自由仅改变调度。固定路线失败不自动把其他品牌结果混入该臂；生产顺位恢复另外计为operational策略。相同query可命中共享的锁定检索缓存，报告实际费用和按独立运行归一化费用，避免先跑者承担全部搜集成本。

S1最多144模型HTTP；S2最多90模型HTTP/90查询；S0最多24；旧数字逐题/三题诊断最多24；独立模型辅助评审预留36。首轮**最多318模型HTTP**，小于原350提醒线；搜索查询≤90，另记MCP握手/协议HTTP，原200搜索提醒线按全部相关HTTP计。评审模型调用也算HTTP，人工评审单列耗时。每次失败、重试、规划、自审、修复都在上限内，不能额外偷偷补齐。

每会话累计输出（含思考）≤48000 token、累计输入≤240000 token、单请求逻辑输出上限16384 token（包括思考），由既有StockQA映射实际wire参数并保存安全请求体hash；两次并行在发出前预留上限，不能事后超支才发现。不同provider字段名不同不是缺口；无法约束或辨认实际输出/思考语义才标qualification gap，不暗改实验条件。公司并行≤2，单公司模型并行≤2，全局物理并行≤4；现有StockQA更严限额优先。共享context最多12000字符短证据，单来源最多2000字符；若做更长context消融必须单独登记。

**S3 确认/扩展。** 先按冻结质量规则暂选至多两策略，再用MiMo-v2.6-pro在开发集配对复验；不足两臂达标不强凑。之后6家留出公司各30题基准验证，若其适用题总量不足30则完整保留实际题数并在发请求前锁定分母，不借用不适用题凑数。Flash/M3仅在真实接口资格通过后加入同证据比较。搜索再按Brave、Tavily、ZAI MCP分别比较同一策略；native web_search作为不同工具能力路线单列，不能宣称纯搜索品牌因果差异。只有必要时增加C无自审/C自审/C独立复核消融，不做四模型×四搜索×所有策略全排列。

S3按S1/S2结果在执行前追加固定矩阵、预算估计和试次，保留旧失败与所有新费用。用户已授权超原US$25/350模型/200搜索提醒线继续；接近或超出先告知累计与下一批，不重新索取同一授权，不把提醒线当可无限循环的理由。每公司上限仍是实验条件，不能因某臂答得差偷偷放宽。

## 4. 如何判胜

按以下顺序报告，不把费用与正确性加权为一个分数：

1. 原计划槽位完整性：S1每臂72槽、三臂216；S2每臂36槽、三臂108。共324次执行仅36个公司×题目组合，S1/S2不得混算准确率；18数字探针、资格与辅助评审另列。首轮与终态分别统计。未完成、invalid、限额失败都不从分母删除。交齐unknown仅是执行完整。
2. 严重错误：错主体、错期、十倍单位、计划当实绩、伪造来源、隐藏思考泄露分别计数。理由与数值冲突也算错误，不能只验数值字段。
3. 事实支持：所有关键断言及评分依据均审，引用可访问不等于蕴含；有支持/部分支持/矛盾/无法核实分列。
4. 有效覆盖：独立参考认定可回答题中，有依据、主体口径正确且答案合格的比例；已回答精确率与覆盖同时报告。unknown不是自动正确，也不是一律错误。
5. 评分质量：只在具备独立可辩护区间的子集衡量区间命中及方向/锚点支持；主观无参考项明确排除，并报告排除分母。不得把agent自己的分数当参考。
6. 自审净收益：错误→正确、正确→错误、无新增证据改分；独立复核同理。被触发与随机抽样复核分别报告，选择样本不能冒充总体。
7. 质量合格的候选再比：总费用/合格答案、总费用、公司真实wall、请求耗时之和、搜索次数、思考/输出、失败/限额等待。小样本报逐公司与中位/范围，不报看似精确的总体p95。

预设非劣容差2个百分点，只是确认阶段目标；3家公司不足以证明非劣。按公司配对、公司聚类计算差异与不确定性；重复不能扩大公司n。小试中出现新的严重错误或覆盖明显降低者先保留问题，不能因快/便宜胜出。留出区间仍宽则结论为证据不足，继续基线，不强行宣布赢家。

最终评审看不到策略、模型、花费和自审过程；两评审共享重叠子集并报告一致性，分歧裁决留记录。若仅由LLM/agent辅助审查，明确不是人类金融gold，不据此自动关闭F05。最终回答的全部理由也在审查域，不能只对显式claims数组评分。

## 5. 缓存实验独立计量

所有臂共用稳定前缀规范，不能仅优化C而让A重复随机前缀。主实验报告自然缓存、实际顺序和usage可观测覆盖；不把“应用缓存为空”叫供应商KV冷。供应商无法证明清空，则cold_state=unknown。

另用非金融合成任务做资格探针：稳定长前缀P+不同尾部至少3次，以及在开头变动的对照；重复时保留足够间隔，记录首轮写入/共同前缀发现成本。它只测缓存协议，不测金融准确性。把其费用纳入本轮总资源；预热的成本与后续摊销都报。缓存读取token/可观察输入token加上缺usage请求比例，不能缺失填0或只报命中的请求。

全历史追加、证据epoch+delta、短选择context三种内存方式可在胜出策略内部消融，不混进第一阶段全部矩阵。cache命中率最大但无用context更多的臂不优先。跨模型、端点、账户的cache不假设共享。

## 6. 失败、版本与轻资产留档

模型限额/超时分别保留planned_model与actual_model、request ID/attempt ref、拒绝原因、cooldown和全部费用。固定模型比较以原分配臂统计；fallback另作operational分析，不把混合结果冒充原模型。发送结果未知由原owner查账再决定，不建立第二队列。

研究输出采用原answer-content；另外的研究封套记录experiment/run/company/arm/repeat、原题对象hash、证据epoch hash、实际模型/工具/参数、开始结束UTC、request refs及逐槽execution_status。它不是正式Observation，不含伪造owner确认、ACK或production资格。原题hash与版本不同则新实验revision；旧结果不可覆盖。

恢复只重做未完成或证据依赖已变的题；新资料不能悄悄使旧答案对应证据失效。保留前后答案版本和依赖hash。隐藏思考仅为多轮协议在内存传递，永不进入最终JSON/公开日志/交接；崩溃后新session segment从可核事实重建。

网页/检索片段及其中的指令一律为不可信数据，不能改变题义/锚点、扩大工具权限、读取gold或要求输出私有内容。不下载财报或整页，不保存网页全文。短证据context在隔离工区保留至盲评和复核完毕，长期仅归档可重建实际输入所需的最小短片段、结构事实、公开URL、定位、hash和最终答案；若来源不宜留摘录，标明无法精确复放，不再声称仅凭hash可重建。清理只删除本次清单内、路径核实的临时文件；保留待核未知请求收据，终止自有进程后再清理。不动用户原文件、数据库、名单或旧实验归档。
