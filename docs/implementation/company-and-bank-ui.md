# 公司快扫工作台：当前使用范围

2026-10-26。此页说明实际可用产品及数据，取代把历史施工包验收误认为全股票池已经完成扫描的理解。

## 打开使用

在 invest-quick-scan 根目录运行：

```powershell
python scripts/open_dashboard.py
```

终端打印本机网址，默认 `http://127.0.0.1:8765/#/dashboard`；端口已用时会打印其他可用端口。Ctrl+C停止。入口复用同级 `iqs-question-bank-ui-lab` 的服务，启动时重建题库/旧草稿展示数据，不执行测试、不调用LLM或搜索；打开页面只读，明确提交名单或导入操作才经原owner写入。

`--no-refresh`仅查看已构建快照；`--ui-root`指定UI源码目录，`--data-root`指定IQS数据根；`--plan`只查看启动命令。独立VIEW导出浏览器仍用 `view_quick_scan.py --bundle ...`，两种入口的数据范围不同。

## 工作区与操作方式

顶栏按总览、扫描、公司研究、题库、设置分组；原子页面和旧URL保留。公司名单及选择器支持名称、代码或唯一ID搜索，同名不同实体分开展示；名单每页50家。正式结果以题义选择原评分字段，进入详情再返回会保留条件、页码和原有效快照，快照过期须重新查询。历史按唯一观测选择，一条记录不做双栏比较。

设置页默认用普通字段编辑连接、模型顺位、额度组、并发和预算，高级JSON保留未知字段。保存由原StockQA校验，原配置被其他进程修改时拒绝覆盖，须重新读取；保存不自动扫描、不授准入或扩大旧账本额度。

题库卡片和题号支持键盘操作，抽屉支持Tab循环、Escape关闭及焦点返回。历史矩阵默认3个基础模块，可展开48模块；宽表只在局部横向滚动。旧草稿选股器默认只显示本次条件，全部适用性在展开区。

## 基础题如何执行

新快扫默认覆盖完整基础集合，不再从旧24题文件取默认输入。只验证出题、零模型调用：

```powershell
python scripts/question_sets.py basic --output runs/basic-questions.json
python scripts/thin_scan.py --company "宁德时代" --out runs/basic-dry-run --dry-run --as-of 2026-10-25
```

`basic_questions.json`是StockQA兼容导出；`main_questions.json`及显式 `--questions docs/implementation/questions-24.json`保留历史兼容用途，不是新扫描的完整基础模板。完整类型/行业/阶段组合与新2.5冻结路由命令见SKILL.md。quick/full都保留基础框架；题数预算只能延后选配题，预算连基础/关键风险都容不下则明确报错。

杜邦和五力逐题回答，但不混入核心质量均分。个别比率对银行或商业化前公司没有经济含义时，保留题目、说明依据并标不适用，不能强行打中间分；缺资料仍是证据不足。

## 产品操作

工作台新增扫描任务、生产结果、历史与模型、信息与关系、名单维护、模型/连接设置和环境检查。生产结果支持原三态分数组合条件、市场/行业及同一snapshot分页；逐题可看分数、理由、来源、时间、模型/修订和原版本。缺失信息不补造，原不具备的关系/质量汇总明确显示不可用。

名单操作先检索已有身份，明确选择entity_id、填写理由、预览后再加入/移出/恢复/保留。不会只凭名称新建或合并公司。已认可的214个既有实体现已进入原StockWiki名单`UNI_IQS_APPROVED_214_20261025`，原身份状态保持不变。

任务页先选择公司、信息截止日、quick/full及原分析主体，预览实际组合题库；无主体时可明确选择“仅法律发行人”，多挂牌须选择原证券。确认准备在后台调用原路由、确认和准入，不调用模型；首次准备可能需要数分钟。中断后查看准备job并核原状态，不能重复确认或盲重发。

准备完成后选择完整公司组，可全选无歧义组、预览并启动批次。每个公司实际经营题与证券题分原scope执行，跨公司并发由配置限制；暂停在scope/公司边界排空，重启后需明确恢复。已有任务先“核原状态”，再按开放的操作恢复。

完成后可按原包或批次提交“入库并对账”，后台交付job复用原封存结果；accepted/partial不等于delivered。原导入列表仍兼容；原回执再对账StockQA，pending保留原状态。完整六步见[总README](../../README.md#在界面跑公司)。

首次使用的本机连接、原运行配置、原包全部字段与HTTP说明见[产品接口与部署](dashboard-product-contract.md)。配置模板在examples/dashboard.config.template.json；本机配置config/dashboard.local.json已被Git忽略，不填写密钥。

本次将原r25真实CATL IQS_05封包通过产品HTTP导入StockWiki原工作区，并从独立owner DTO绑定接收目标，将exact ACK应用到原StockQA，实际状态delivered。原冻结24题manifest不回写；这是一题工程闭环，不代表36题全部完成或金融准确性通过。原工作区标签isolated_research，与旧草稿快照分开。

全214实体与所有当前题面可浏览，但多数公司还没有正式观察。12旧运行仍保留未绑定版本和模型缺失，不参与严格版本化结论。任意公司自动组合/原准入登记、完整公司组批跑、异步交付和显式恢复已接线；原完整36题准备与真实旧包ACK闭环均有工程证据。自动准备当前仅支持原owner policy 1.0/1.1；高级策略明确显示缺口，不降级。当前本机`prepare`仍空、模型顺序和新预算尚未配置，因此不能直接宣称214家公司可立刻全部开扫。原r25预算已用完，不能重发cold。

本轮按边界运行集中集成/原ACK/前端回归和真实CUA浏览，整节点独立审查，不每次小改运行小时级全套。进度和证据见根PWF当前M阶段；本轮体验整改与原发现对应关系见[整改验收](reviews/ui-remediation-2026-10-25/README.md)。

## 较长扫描与旧任务恢复

设置页“新扫描确认有效期（小时）”允许0.25–24小时，默认1小时，较长扫描可选4小时。保存只改变之后明确准备的新确认；不续期已有确认、不增加预算。过期任务须核原状态并在相同截止日/主体/模型下重新准备，原工作和已有结果按原owner接续。

旧服务退出留下活动启动引用时，先“核原状态”，若原工作完整且无未知/在途，使用“归档已停止任务（保留工作和结果）”。服务核进程退出/原PID复用后仅退役本地引用，保留原库、检查点、费用和历史。归档任务只可检查，不再恢复启动。临时原准入ledger busy时等待正在进行的准备完成，再核原状态/恢复同一批次，不能反复新建。

任务进度显示原scope工作快照，区分已保存、在途、待问和失败，并显示缓存与核实时间；无原检查数据时明确未读取。该快照不是派发许可，也不表示整家公司、入库或金融质量已完成。
