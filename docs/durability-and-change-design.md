# 优势的持续性与产业变化：方法及skill设计建议

日期：2026-09-19。状态：讨论设计，未加入题库或评分代码。对应[总体设计](stock-pool-design.md)和[实施路线](implementation-roadmap.md)。保持现有24道通用题、轻量联网问答和独立恢复观察，不另建预测模型或公司文档库。

## 1. 对“不变与变化”的判断

这是分析企业价值的有用视角，但“不变”更准确的含义是：在明确的业务边界、时间范围和条件下，仍能持续创造超额回报的机制。品牌、渠道、规模是资源与位置，其经济价值要看客户是否继续在意、替代者是否能绕过、公司能否保留利润。

因此需要连着问：客户需求是否持续 → 满足需求的方式是否改变 → 原优势所依赖的条件是否仍成立 → 谁能取得新的利润 → 扣除转型代价后，现有普通股是否受益。

以用户提出的胶片例子作机制说明：记录与分享影像的需求可以继续存在，但满足需求的介质和价值分配可以改变。旧技术中的品牌或规模领先，不自动证明旧利润能保留，也不证明能力已迁移到新业务。这不是对某一家公司的完整历史评价。

替代品可能用不同方式满足同一需求，行业结构也会随技术、渠道和规则变化；[哈佛商学院五力说明](https://www.isc.hbs.edu/strategy/business-strategy/Pages/the-five-forces.aspx)支持这一分析区分。我们的具体问卷和观察策略仍需自行设计和校准。

## 2. 分清四种“优势”，避免静态标签

| 优势表述 | 必须补问的经济机制 | 条件失效的可能路径 |
|---|---|---|
| 品牌 | 是降低选择风险、获得溢价，还是只带来知名度？客户是否持续付费？ | 产品评价方式、信任来源或消费场景改变 |
| 渠道 | 控制稀缺触达、售后服务或客户关系，还是仅控制旧交易入口？ | 新渠道绕过旧入口，服务可被替代，客户采购迁移 |
| 规模 | 哪一段单位成本随规模下降，竞争者追赶需要什么投入？ | 技术改变最低有效规模，旧资产成为固定成本负担 |
| 数据/技术/认证 | 是否独占、可用、难以替代，并持续改善客户结果？ | 数据失效或容易获取，技术换代，认证价值不再重要 |

任何优势都记录“适用业务、有效条件、时间范围、失效信号”，不要求LLM给虚假的精确寿命。短期难以复制，与长期不会失去价值，是两个不同判断。

## 3. “会变化”需要看利润归属与企业的应对

产业增长或生产效率提高不自动变成公司利润。AI情景仅作分析示例：若所有竞争者同样降低成本、客户随即要求降价，使用AI的公司可能提高效率但留不住节约；如果公司掌握难替代的工作流、客户关系或其他瓶颈，则可能保留较多价值。方向需要针对具体业务取证，不能把“使用AI”直接计成高分。

企业能看见机会、能开发产品、能获得付费客户、能赚钱、能形成新优势，是不同阶段。旧业务执行稳定不等于能调整组织和激励去承接新业务。Teece将这类能力联系到识别机会、调动资源和重新配置组织/资产，见[原始研究](https://sms.onlinelibrary.wiley.com/doi/10.1002/smj.640)。应用时检查实际投入和兑现记录，而不是让模型给“管理层有远见”的印象分。

还要区分恢复和上台阶：周期修复可以回到正常经营水平；产业变化带来的新台阶需要新增客户价值、经济性或能力的证据。两者可能共存，但不能以低基数增速证明第二增长曲线，也不能用结构性替代推断行业一定周期回归。

## 4. 优先深化既有问题

保持通用24题，先在相关题的证据要求里贯穿这一逻辑，不给所有公司强加“AI转型”问题。

| 判断 | 现有题目 | 建议补充的证据口径 |
|---|---|---|
| 客户的不变需求 | IQS_01/02 | 客户真正购买的结果与当前产品形式分开；持续需求不等于持续购买同一产品 |
| 存量优势及经济回报 | IQS_05/06/10 | 明确优势机制、成立条件与正常化回报，避免品牌/规模自动得分 |
| 优势失效风险 | IQS_18 | 产业变化能否绕过原护城河；替代速度、暴露范围和防御证据 |
| 新利润归谁 | IQS_04/19 | 技术改善后客户、供应商、平台与公司如何分配价值；可触达需求与宏大行业空间分开 |
| 公司能否兑现机会 | IQS_07/09/20 | 新产品、付费采用、组织调整和承诺兑现的证据，而非只统计研发投入 |
| 新投入能否增值 | IQS_14/21 | 新业务收益、旧业务被替代、必要投资与融资摊薄共同考虑 |
| 价格要求什么 | IQS_22/23 | 公司受益和股票值得买分开；不能忽略价格已经要求的成功程度 |

这些是未来问卷修订建议，本轮没有改变现有题目文本、锚点、ID或历史分数。

## 5. 重大变化时，拟增加三道桥接诊断

适用触发：有具体产业变化，且可能实质影响公司的利润来源、资本需求或竞争地位。技术、渠道、监管、能源结构等都可能触发；行业热词或管理层宣称本身不够。只取最重要的1—2项变化，按实质分部分析。

以下为问题草案，尚未分配生产question_id。先与现有题对照，能通过扩充原题证据解决的部分不重复计分；确需单独判断的部分放入按需诊断，默认不进入质量均分。

| 拟补充判断 | 1分锚点 | 5分锚点 | 10分锚点 |
|---|---|---|---|
| **原有优势能否以合理成本迁移到新业务的关键环节？** | 关键能力不适用且迁移成本高，现有资源构成负担 | 部分能力可复用，仍需建立重要新能力 | 客户、技术或其他难复制能力已在新业务中验证，迁移成本可承受 |
| **组织能否及时调整资源与激励，包括主动替代旧业务？** | 明显利益冲突/组织阻力阻碍必要调整，已有失败证据 | 方向和投入明确，但资源配置或执行尚未充分验证 | 人才、预算、激励与业务取舍已实质调整，连续兑现可核实目标 |
| **扣除旧业务损失、转型投入和融资代价，新变化是否增厚现有股东的持续经济利益？** | 新收益不足以弥补可见旧业务损失和投入代价 | 有合理正向路径，但净效果受关键条件制约 | 有经营和经济性证据支持明显净改善，保守条件下仍能为现有股东保留价值 |

没有资料是null，不是5分；没有实质适用变化是不适用，不是低分。早期机会可保留假设和跟踪标记，但不能因为想象空间大就把兑现证据评为高分。

第三题只要求有据可查的方向、机制和必要区间，不强迫LLM生成精确财务预测。需要分部收入、利润和资本的完整情景计算时，交给revenue-forecast与invest-*。

## 6. 输出不能压成一个“变化受益总分”

至少分开展示：存量优势及适用条件、优势受侵蚀的路径、新机会及兑现阶段、能力迁移、净经济效果、市场价格要求。积极与消极变化可以同时存在；新业务机会不能平均掉存量业务面临的永久损害。

建议的非互斥观察标记（尚未实现）：

- 优势持续：旧有盈利机制仍有支持，不要求参与热门产业才有价值。
- 机会待验证：有具体机会与部分能力基础，但缺少商业兑现。
- 优势随变化增强：变化扩大了原优势的适用范围或经济价值，已有机制与证据支持。
- 优势受侵蚀：原来有效的品牌/渠道/规模前提开始失效。
- 转型过渡：旧业务受损与新业务成长并存，净效果与资金衔接需要单独观察。

这些标签按不同变化/分部可以同时出现。例如同一集团旧产品受到替代、新产品获得机会，不应强迫归为单一“受益者”。筛选时按用户策略查看各维度、证据等级和风险，不输出机械的普适买卖判断。

与已实现recovery_watch联动：优势仍在而短期盈利低→恢复观察；变化破坏了优势的成立条件→结构性风险；恢复叠加新机会→两组证据都展示。低谷可恢复和未来能上新台阶不可互相代替。

## 7. 轻量记录与持续维护

在评分依据中保存如下简短字段即可：`advantage / business_scope / holds_if / could_break_if / change_driver / mechanism / milestone / falsifier / horizon / evidence_refs / as_of`。正面机会和负面风险分开记录；类型、分数和检查等级复用既有契约。它们是评分说明与路由元数据，不是提前扩展完整纯信息数据库。

保存每次判断及实际信息时点。新证据出来后，对同一假设记录增强、削弱或证伪；只有同题、同口径、同锚点的分数才能比较变化。模型换版导致的评分差异要与企业真实变化区分。

每次更新优先复问“原优势条件是否破坏”和“下一里程碑是否兑现”。不要求每次重答所有题，也不根据模型自述制造实时监控能力。持续优势可低频复核，出现可知重大变化后定向重问；问答执行仍只走StockQA。

## 8. 实施与验证建议

1. M0先补齐现有题的证据口径，比较是否足以覆盖上述联系；决定三道桥接诊断的最终取舍后，再版本化题库。
2. 将其纳入60只校准集的分层案例：优势延续但无热门主题、原优势被绕过、效率提高但利润被客户拿走、旧业务下降且新业务尚不足、能力迁移成功、机会重要但证据仍弱。
3. 验证不因无AI业务给低分，不因使用AI直接给高分，不将旧业务高分复制到新业务，不用新业务的小额高速增长抵消大额旧利润流失，不把缺证据等于无机会。
4. 后续轻量库保存条件与标记，页面列新旧业务双方证据；深研才建立完整情景和估值。

本设计重点是建立可被新信息更新的判断链，而不是继续堆叠孤立评分项。本文形成时题库为2.1.0；当前已升级3.0并增加事实库及稳定输出。本文专用的优势迁移/变革标记及桥接设计仍需按相关任务逐项验收，不能因版本升级视为全部实现。
