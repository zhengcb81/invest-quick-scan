# 轻量股票池实施路线

日期：2026-09-19，更新于2026-09-22。状态：待实施的路线图，不是已经完成的功能清单。对应[总体设计](stock-pool-design.md)及[名单、续扫与研究联动方案](universe-and-operations-design.md)。本轮只交付规划和规划工具，不实施外部生产功能、不调用收费模型、不批量创建公司。

2026-09-22已扩为[细粒度实施包1.4.0](implementation/README.md)：73张单一拥有者任务卡、162个验收场景、28条固定约束及G0—G6审查关口。[各项目交付](implementation/cross-project-delivery.md)和[一键开启设计](implementation/one-click-launch.md)明确外部目录的接口、配套安装、启动与最终整体验收。后续模型按任务ID实施；本页保留里程碑视图。

本轮已补本地评分3.0、事实61题及标准观察/比较工具；这不表示StockQA/StockWiki生产任务已通过。首次启动、自动准入W13、模型对照Q11、快照查询W14统一见[全局契约](system-contract.md)。

## 实施原则与交付顺序

先把现有评分问卷做成可信、可恢复的筛选闭环，再编制纯信息问题集和产业链检索，最后扩容。问题内容、问答执行、数据查询分别沿用明确的项目归属。

样本路径：**10家公司连通验证 → 60家公司评分校准 → 200家公司运行验证 → 在该样本上加事实画像 → 扩至约2,000家公司**。上述规模均按独立公司计，多挂牌只计一次，证券层任务与费用另报。名单工具可先形成约2,000家候选版本；形成名单不等于立即发起全池扫描。

| 阶段 | 交付成果 | 主要项目 | 依赖 |
|---|---|---|---|
| M0 契约和指标冻结 | 对象、名单规则、字段新鲜度、问答/查询/补扫协议及用户模型策略 | invest-quick-scan；StockQA/StockWiki接口对齐 | 当前规划 |
| M1 联网问答修复 | 真实搜索、原始分数传递、可空评分、顺序模型接线、10家公司 | StockQAbyLLM | M0 |
| M2 评分闭环 | 名单小工具、轻量入库、60家公司校准、白名单、基础查询 | StockWiki + invest-quick-scan | M1；名单工具离线部分可先做 |
| M3 批次可靠性 | 200家公司、限额、接续、故障冷却、定向刷新与导入回执 | StockQAbyLLM + StockWiki | M2 |
| M4 纯信息与主题检索 | 事实问卷、术语/关系、主题及行业skill接入、深研交接包 | invest-quick-scan + StockWiki + 两个消费技能 | M2；批量运行依赖M3 |
| M5 扩容与维护 | 三市场约2,000家公司、公平调度、版本化维护与覆盖报告 | StockQAbyLLM + StockWiki | M3；全量事实依赖M4 |
| M6 配套交付与一键开启 | 统一setup、公开控制/配置接口、实际技能加载、启动/恢复、配套升级及真实端到端 | 各实现归属项目；StockWiki提供统一入口 | C07先由G0冻结；最终G6同时依赖G4、G5及全部任务 |

company-wiki不承担新增快扫评分、原件归档或批次运行任务；仅在已有主档/映射可复用时按只读契约接入。所有新增路径和命令名都要在各自拥有者项目实现，不能靠skill直接越界写库。

## M0：先固定能够互通的最小契约

- [ ] 将轻资产边界写入下一版SKILL入口与运行协议：仅问答填充、只留结构化结果和引用，不保存网页正文或公司文档，不要求company-wiki建档。
- [ ] 清点24道核心题、类型替代题及行业/阶段补充题，给每个可筛选判断增加稳定metric_id，记录原question_id与rubric版本；杜邦/五力只作诊断。
- [ ] 根据[不变与变化设计](durability-and-change-design.md)，先补优势有效条件、产业变化与利润归属的证据口径，再决定最多三道能力迁移/组织调整/新旧业务净效果诊断的取舍；不新增机械总分。
- [ ] 明确entity/security/segment作用层；将估值与证券特有权益题分出，识别可复用和必须重问的部分。
- [ ] 定义scored/routing/facts三类回复信封；本阶段只实施评分和路由，facts预留契约，后续不得用假分数承载事实。
- [ ] 定义score:null及缺失原因、信息日期、来源引用、搜索执行receipt、token/搜索耗用、运行状态和版本字段。
- [ ] 定义screening检查等级、规则三值逻辑和critical gate；明确现有v2 accepted_ids不自动转换，新旧协议显式区分。
- [ ] 定义轻量名单工具：主档/成分/用户清单导入、独立实体去重、分层候选、manual_pin、增删恢复、歧义处理、提名与成员版本；约2,000家为独立公司总量，三市场配额为可重叠软目标。
- [ ] 固定首版分层种子规则、证券类型范围及数据缺失处理；60%广覆盖/25%细分补盲/15%变化与特殊情形只作初始建议，不以当前盈利或高分快扫为入池必要条件。
- [ ] 定义逐字段TTL/提前失效、原始信息时间、unknown冷却、逻辑待办键和执行状态；严格区分运行完成与评分可用。
- [ ] 定义用户排序模型策略、能力预检、故障类别、统一重试/费用上限和恢复首选模型的条件；复用StockQA ProviderCascade，不造第二套客户端。
- [ ] 定义消费者capabilities/coverage、search_companies、get_profiles、export_candidate_set、request_refresh、nominate_company与冲突反馈契约；M2先供评分基础查询，M4再提供完整事实检索。
- [ ] 对齐只读身份接口和StockWiki导入接口；无company-wiki条目、无正式StockWiki档案均可扫描。
- [ ] C07冻结配套版本、独立解释器/公开控制入口、安装/技能加载hash、统一setup/start/stop/resume、预算连续性与最终G6资格；不能将跨项目接线留到最后临时设计。

产物：正式数据schema、metric映射表、示例交换包、规则schema、schema版本迁移说明。本文随附的design-examples.json只是讨论样例，不能当已生效协议。

验收：一般工业、银行、保险/REIT、亏损成长、周期、早期公司和多挂牌案例均能无歧义表示；未知不会产生默认分数；规则无法误把实体分数与另一证券报价拼接。迁移旧结果保持原题/锚点版本，不强行补造新metric历史。

## M1：修好StockQA，跑10家真实联网样本

- [ ] 修复当前AnswerGenerator成功分支固定score=5，以及失败/解析异常默认分数的路径；优先原生保留null和状态，旧接口仅保留明确的兼容读取。
- [ ] 按实际提供商接入搜索工具/搜索开关；保留请求标识、搜索事件或有据可查的执行metadata。提供商不能证明执行时标记search_unavailable。
- [ ] 同步/异步客户端和CLI保持相同分数与来源语义；配置与密钥仍在StockQA，不复制到skill。
- [ ] 增加结构化回复透传、独立题ID及来源关联；拒绝多余/丢失题目、答错公司和外内分数冲突，不用正则猜分。
- [ ] 保证日志只保存问答与必要metadata，不落地搜索网页正文、PDF或附件。原始LLM调试回复设保留期。
- [ ] 审计ProviderCascade的真实调用链并接入用户有序模型/能力配置；验证服务失败切到后序模型，低分/unknown不触发择高分重问。配置与密钥唯一留在StockQA。
- [ ] 先单题探针，再完成10家独立公司小样本，包含不同市场和至少一个难分类对象；证券层另测，保留实际费用和失败原因。
- [ ] 先逐题执行建立基线；multi-question pack只做少量对照，未经比较不默认启用。

产物：上游修复、搜索receipt样例、脱敏结构化问答包、小样本费用/失败报告。

验收：输出分数真实来自模型有效回答；未联网/来源缺失不伪装成功；可空结果贯穿全链路；每个有效分数能关联问题及来源。至少完成一个真实搜索调用，离线mock通过不能代替。联网试点使用已配置提供商与显式批次预算；若尚无预算，先完成全部离线工作，留下最小待运行批次。

## M2：名单小工具、60家公司校准与第一个白名单

- [ ] StockWiki新增轻量quick_scan存储迁移、单写入入口和事务式导入；MVP只实现身份、评分、引用、运行、检查、数据集、规则结果等必需表，事实表到M4再加。
- [ ] 实现universe导入/预览/应用、add/remove/restore/pin、跨挂牌关联、diff/explain及提名列表；形成带来源与入池理由的候选版本。用户加一家公司只新增其缺口，重复代码或另一挂牌不重复新增实体。
- [ ] 可先生成约2,000家离线候选名单，但本阶段扫描仍限校准集；不得因名单形成就自动启动2,000家公司付费任务。
- [ ] 实现基础capabilities/coverage、批量画像查询和候选导出；只有粗分类与评分时如实报告事实域未上线，不提供假设备/材料关系。
- [ ] 建立历史观察与当前视图；原始评分保留，更正追加；批次重导入幂等；未完成数据不会被标为完成。
- [ ] 实现all/any规则、比较符、适用类型、时效、覆盖率和检查等级；输出pass/fail/unknown及条件明细。
- [ ] 建立60家公司校准集，初始按主要覆盖市场分配各20家，另加挂牌映射；覆盖不同规模、经营类型、阶段以及多挂牌、负净资产、负利润、周期顶底和业务转型。
- [ ] 选20家公司做重复问答；对临界高分、关键风险和来源冲突做独立联网复问/小范围人工抽查，并对实际可能启用的备用模型检查尺度差异。
- [ ] 固定首批评分锚点与比较组；未经校准的类型仅显示画像或使用专属规则，不参加统一排名。
- [ ] 输出一个质量筛选示例和一个成长筛选示例，并逐项解释命中/落选原因；阈值是用户可调整的策略配置。
- [ ] 独立导入recovery_watch和政策版本，建立恢复观察池：质量门槛未过也保留优点、低分、反证、恢复里程碑和风险。支持与质量池并集，禁止先按质量门槛删除全池对象。
- [ ] 校准暂时低谷但优势仍在、已有经营修复、无催化、资金撑不到恢复、结构性衰退和严重摊薄等正反例；本地2.1观察逻辑已存在，跨公司池与卡片仍待实现。
- [ ] 接入可选的company-wiki既有身份引用，验证断开联动仍能完成问答和独立导出。

产物：名单小工具与候选版本、60家公司版本化数据集、规则配置、基础查询、检查记录、可解释白名单、问题/模型稳定性报告、简洁表格或页面。首版无需开发复杂仪表盘。

以下是建议的放行目标，均尚未实测，需在试点中确认可达性和费用：

| 检查项 | 初始放行目标 |
|---|---|
| 对象身份 | 校准集无串公司、错误跨挂牌合并或错误报价归属 |
| 结构成功 | 在限定重试后，逐题契约通过率≥99%；同时单列unknown和无来源比例，不能靠丢弃失败样本达标 |
| 引用覆盖 | 所有screening可用分数有逐项来源引用及搜索执行记录；这不等于已证实原文真实支持 |
| 分数稳定性 | 重复运行中，可比较有效分数至少90%相差≤1；另外报告缺失和状态变化，不能只报共同成功子集 |
| 阈值稳定性 | 校准样本的同一规则入围状态一致率目标≥90%，重点单列7/8/9区间 |
| 关键风险 | 人工/独立复问抽查发现的重大实体、来源或事实错误全部纠正后再放行；不声称样本外错误为零 |
| 规则正确性 | >8与>=8、null、N/A、过期、critical gate、类型不兼容及AND/OR三值逻辑的固定用例全部通过 |

未达到稳定性目标时优先改锚点、比较组、搜索/问题pack或提高特定字段的检查门槛，再重测受影响样本；不通过反复运行直到某一次高分入围来“修复”结果。

## M3：200家公司验证运行成本与恢复能力

- [ ] 复用StockQA异步底座，补足真正需要的批次清单、检查点、限流、预算、取消和续跑；避免在skill或StockWiki另造API重试器。
- [ ] 支持按对象/题目缺口和字段TTL增量补跑；今天再次运行只复用有效旧观察，不篡改其信息日期；价格、经营与风险字段分别调度。问题新增仅补新题，规则阈值变动不发问。
- [ ] 持久化领取租约、逐题检查点、冷却及剩余待办；已返回的题保留，pack只补失败/缺失题。新成员并入增量待办，普通公司保留首次覆盖和最久未更新的公平份额。
- [ ] 接入StockQA轻量outbox与StockWiki幂等导入ACK；模型成功/入库失败只补导入。外部请求结果不明单列outcome_uncertain和费用预留，不承诺不支持幂等的提供商绝不重复收费。
- [ ] 持久化提供商故障冷却和受限健康探测；所有模型不可用保存retry_wait；用户总预算耗尽停全部派发，不能通过备用模型绕过总限额。
- [ ] 检查提供商批量能力；若question pack质量达到M2基线，再采用4—8题一组；未通过则保留逐题路径。
- [ ] 网络超时、限流、解析失败、局部失联、额度到达和进程重启均有明确状态；已取得且有效的结果不重新向模型发问，结果不明按显式策略处理。
- [ ] 同一API调用只有一个重试拥有者，预算同时记录失败和复核消耗；保护费用上限而非只看成功请求数量。
- [ ] 验证200家公司批次、主动中断与恢复、两运行同时领取、结果成功但导入失败、重复导入、数据库备份恢复；加入A/H同实体、近期全部有效、仅风险过期、unknown冷却及模型顺序故障案例。
- [ ] 接通有字段/实体白名单和预算的request_refresh；消费技能请求3家某些字段不得隐式刷新整个池。
- [ ] 在200家公司真实试点前完成W12一致性备份/恢复及临时目录演练；不能等到M5才补齐本阶段验收所依赖的恢复能力。
- [ ] 给出实际每公司/每类问题的调用数、token、搜索费用、耗时、数据大小与可用率，按这些数字估算全池预算。

验收：恢复后不漏题、不重复产生权威观察；高优先级新任务可排队，已有结果可查询；预算耗尽停止新派发；结构化数据目录没有新增公司文档；规则查询在实际机器上达到可交互水平，记录实测延迟而不是承诺固定性能。

里程碑：至此评分阶段交付完成，可以维护一个真实可用的小型评分股票池。完整纯信息问卷从下一阶段开始。

## M4：纯信息问题集与产业链检索

- [ ] 根据M0事实契约，新增专门的非评分问卷：业务/产品→材料与设备→下游应用→供应商/客户关系→商业化与实质性。信息不明使用unknown，禁止为兼容接口硬塞1—10分。
- [ ] 按经营类型/行业选择事实问题；每题只采集能影响关系检索的内容，不写公司百科，不补无来源的详尽供应商名单。
- [ ] 建立最小术语表和中英别名；版本化主题定义与新增术语审核；保留原始表述，不能静默改变已有关系语义。
- [ ] 保存有方向、有分部、有依据、有状态、有时间的业务关系；区分公开披露、第三方报告、行业推断和模型假设。
- [ ] 先在200家公司样本中补充事实；AI硬件作为首个演示主题，另选一个非AI主题检查模板是否过拟合。
- [ ] 实现关键词/别名召回、关系与状态过滤、质量规则交集、公司去重和证券保留；全部结果展示命中路径。
- [ ] 加入负向测试：设备使用者、纯软件使用者、研发未商业化、公司否认合作、关系过期、同名异体、材料泛用途、行业推断均不能误入strict供应商池。
- [ ] 输出深研交接包并验证被StockWiki读取；其source URL只能标线索，不冒充company-wiki manifest/span或正式模型输入。
- [ ] 修改analyze-theme-value-chain：在第5步查询分环节候选，第6步复用合适基础字段；保留先拆链、池外领导者发现、主题收入证据及原有情景模型的义务。
- [ ] 修改industry-research：在第6步先查统一实体与画像，移除“必须有companies目录”的隐含限制，按实际截止日补缺；行业框架PDF处理留在原技能，行业评分与IQS不同量表分别展示。
- [ ] 验证两个消费者的定向补扫、池外提名与冲突反馈；不自动增改长期名单，不把下游引用同一快扫结果的报告当新的独立证据，不回写公司文档。

产物：事实题库、关系schema与词表、主题配置、可解释小股票池、深研handoff示例。

验收：在人工预先标注的正负样本上统计检索precision/recall；strict模式精确率初始目标≥90%，关键反例零误入。探索模式另报召回率和未核实比例；真值缺失的样本不伪称已知。命中“液冷”和“AI”无需依赖三字以上分词；同义词能召回，否定和用途方向能排除。总体主题覆盖率受大股票池范围约束，不承诺找齐全市场所有标的。

## M5：扩至约2,000家公司并建立维护节奏
