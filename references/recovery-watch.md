# 周期低谷与困境反转观察

适用：周期下行/低谷/初步修复、公司自身经营困难，或需要辨别结构性衰退与可修复问题。观察路径可以与质量、成长、估值画像同时存在；质量筛选未通过不等于删除公司。

## 判断框架与问题

分别展示当前表现、正常经营能力、修复证据。现有IQS_10、CYCLICAL_01已要求正常化回报；不能用低谷当期利润直接代表长期能力，也不能用历史峰值或假设中的恢复替换今天的事实。当前低分和重大风险继续保留。

| 判断 | 问题及用途 |
|---|---|
| 低谷是否可逆 | 新RECOVERY_01：周期/执行问题与结构性需求、技术或经济性损害如何区分？ |
| 优势是否还在 | 新RECOVERY_02：客户、技术、成本位置、渠道、团队与关键资产还由谁掌握，是否仍可投入经营？ |
| 恢复如何发生 | 新RECOVERY_03：供给退出、库存消化或公司纠错通过什么机制产生改善；里程碑、时间范围及证伪条件是什么？ |
| 普通股能否受益 | 新RECOVERY_04：恢复前后的现金损耗、投入、债权优先与摊薄，会留下多少改善成果给现有股东？不在此题给目标价。 |
| 能否等到恢复 | 复用IQS_16及类型替代题，和已选TURNAROUND_02、CYCLICAL_02、DISTRESSED_01；资金时间要覆盖合理修复期限，不能只看某个固定季度。 |
| 恢复后的经济性 | 复用IQS_10、CYCLICAL_01、TURNAROUND_04；正常化需求/利润仍须有依据，股价跌得深或低基数增长都不证明价值。 |

四道新增题均按1—10分回答，各有1/5/10锚点，源文件为[recovery.json](../questions/diagnostics/recovery.json)。它们标为`aggregation=diagnostic`，不增加质量、成长或估值均分，也不合成一个恢复总分。与原题的区别是评价“修复所需条件及恢复成果归属”，原题仍评价资本回报、当前执行和存续。

正常化收益需要考虑规模变化和恢复时间，而困境中的优质资产也未必能为现有股权留下价值；可参考[Damodaran正常化盈利说明](https://pages.stern.nyu.edu/adamodar/New_Home_Page/valquestions/normearn.htm)及[困境估值方法](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/valquestions/distresspaper.htm)。这里仅采用判断原则，不建立估值模型。

## 路由

- `stage=turnaround/declining`或`overlays`包含`distressed`时，quick和full均自动追加recovery。衰退进入诊断不代表可反转，诊断可以得出结构性损害。
- 其他情况在profile设置`recovery_review=true`和非空`recovery_rationale`。联网路由题要求对周期下行、低谷、初步修复和暂时经营困难检查该字段。
- 周期低谷中的成熟公司仍可保留`stage=mature`，周期由`cycle_sensitive/cycle_position`描述。单纯股价下跌不触发，普通周期公司也不自动被判断为低谷。
- 人工明确追加时也可在`diagnostic_modules`选择`recovery`并给理由；与自动追加去重。原有杜邦/五力仍只按具体疑问选择。
- 若初次路由漏选，标准画像中已验证的优势与弱项并存，会给出`review_suggested`，再通过同一StockQA工具补问，而非直接判为反转候选。

离线路由示例见[recovery-profile.json](../examples/recovery-profile.json)。该公司和周期位置完全虚构；用`compose --profile examples/recovery-profile.json --mode quick --out-dir 新目录`生成35题，包括原31题和4题恢复诊断。这只是问卷，不是已完成的联网评分。

## 输出与含义

`normalize`输出独立`recovery_watch`，保留政策版本、状态、优势题目/分数、弱项题号、四题及资金题的结果、关键风险和缺口。完整理由、反证、降低评分条件、来源链接仍在对应`questions[].answer`中；展示公司卡片时一起呈现，不仅显示一个标签。

| 状态 | 展示含义 |
|---|---|
| not_assessed | 未做恢复诊断；不能解释为无恢复机会 |
| review_suggested | 有已验证优势与经营弱项并存，值得补问；尚未认定暂时困难 |
| needs_verification | 必需问题或关键风险仍有证据缺口，保留关注理由及待查项 |
| potential_watch | 可逆性、优势和生存条件有一定支持，恢复催化尚弱；有优势待催化 |
| recovery_evidence_watch | 恢复条件及可观察机制已有较强支持；已有修复证据，仍待后续兑现 |
| high_risk_watch | 资金、真实性、公平性或普通股受益存在重大问题；优势照列，显著提示风险 |
| structural_risk_watch | 困境可逆性弱或核心资产/能力已损害，警惕把衰退误当周期 |
| weak_case_watch | 已完成诊断，但恢复论据偏弱；记录不足处，不自动归入高优先级候选 |

`recovery-watch-1`是透明的初筛启发式，不是回测得出的收益模型：

- 原始观察线索：非诊断质量题有效分≥8，同时IQS_06/08/11/20或其实际替代题至少一项≤4，则建议补问。展示所有符合条件的优势，不把未审核的reported_score算作优势。
- 四题和资金题全部有有效分，核心真实性/权益/资金问题无未解或重大风险，且RECOVERY_01≥6、02≥7、04≥6、已选资金题均≥6，才显示potential_watch；其中03≥6则显示recovery_evidence_watch。
- 任一有效资金题≤3、RECOVERY_04≤3或原关键项存在重大问题，优先标high_risk_watch；RECOVERY_01/02≤3优先标structural_risk_watch。若同时缺证据，仍列全部缺口，已知重大问题优先展示。
- 未审核、低置信度、缺题、错误和N/A不会被当成满足条件；缺口产生needs_verification，不自动给5分。高催化分也不能覆盖不可逆损害、资金断裂或股权被摊薄的问题。
- 上述界限在60只试点中校准；当前只支持生成观察标记，尚不是股票池规则引擎。题库/模型或标记政策变更要记录版本，不能静默改写历史名单。

## 股票池使用方式

质量池与恢复观察池分别执行条件，最后按用户策略取并集或单独显示。**不得先用质量综合分门槛过滤全池，再在剩余公司里寻找反转机会。** 即便quality_score为空，recovery_watch仍须展示；但风险标记不转成质量白名单通过。

主题检索同样可选择“所有相关公司”“质量池内相关公司”或“恢复观察池内相关公司”。没有可信报价时，仍可保留经营恢复线索，估值保持unknown。没有催化的优质低谷公司可以低频关注；资金先于催化耗尽的公司单列风险，不能把时间成本隐藏起来。

观察卡片至少显示：当前困难及原低分、仍保有的特征、恢复机制和证据阶段、资金/摊薄风险、最强反证、下一次要验证的里程碑。依旧只保存轻量问答与引用，不采集公司文档。
