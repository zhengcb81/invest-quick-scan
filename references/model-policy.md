# 用户模型顺序、并行、额度与接续

用户填写[model-policy.template.json](../examples/model-policy.template.json)，由StockWiki设置入口调用StockQA配置接口导入；生效配置、密钥和运行状态只属于StockQA。模板在skill内只作样例，不作为第二份运行配置。无需Excel即可配置，后续UI编辑同一配置，不维护两套顺序表。

联网模式、证据context和组合失败处理见[统一使用规范](search-and-llm-playbook.md)。其参考模板不替代本模型策略或C05生效配置，不叠加独立重试预算。

## 怎么填

1. `models`数组从上到下就是优先级。把provider_config_ref填为StockQA已有配置ID，model填为对应模型的实际请求名，启用需要的行；可以删掉不用的行。密钥不写进模板。
2. 同一账户共享额度的模型必须用同一quota_group。模板第一/第三顺位共用account_a，第二顺位用account_b，仅用于说明共享关系；按自己的账户实际情况修改。
3. 填好预算币种、max_cost及max_requests后，把configured改为true。模板默认未配置、模型禁用、额度为0，避免样例被误当无限授权。总预算包括失败、搜索、fallback和模型对照。
4. 设置全局、账户组和单模型并发上限，三层取交集。默认全局4、每账户最多2、单包最多4题只是保守起点，并非厂商承诺。单包题数是上限，初始仍逐题并行；多题合包须通过逐题质量对照后启用。每包仅一家公司的同类回答，路由先于问卷，不能把事实与评分混进旧解析器。
5. 有已知五小时限制的组填window_seconds_hint=18000；没有该信息用null。运行时优先读提供商的Retry-After/reset_at，提示窗口不代表剩余额度，也不是“每次重启再给五小时”。

离线检查命令：

```powershell
python -X utf8 scripts/model_policy.py --input examples/model-policy.template.json
```

这只检查配置结构/引用/预算，不发请求、不确认账户可用。生产doctor、计费探针与安装仍按X03/X04实现。模型顺序、并发和额度以用户填入并保存的版本为准，运行/每个尝试记录policy_version。

## 并行和顺序不冲突

并行的是不同公司或题包，不是默认把同一题同时发给多个模型抢答。正常primary请求按顺序选择首个可用模型；最高顺位只是并发槽满时等待，不偷偷改用次选模型。明确额度耗尽/拒绝/不可用后，才按故障类别尝试下一合格顺位。显式模型对照另设comparison组，各指定模型可以并行，但不能用fallback替代掉某个对照模型。

StockQA复用自身异步/批处理和ProviderCascade，新增持久化账户组限流；skill不另写线程池、HTTP客户端或重试器。派发前原子领取题目租约、账户槽和预算预留；结果后释放槽并结算。并行数与组共享额度不能只存在进程内存，否则两个worker会越限。

## 五小时额度和故障

| 情况 | 执行行为 |
|---|---|
| 确认额度耗尽/五小时窗口拒绝 | 保存错误类别、组ID、observed_at、reset_at来源；组级熔断，未派发请求尝试下一组/模型 |
| 相邻顺位共享同一耗尽账户 | 一并跳过到下一个可用组，不能换模型名绕过同一额度 |
| 普通429/短期限流 | 尊重Retry-After，按统一有界重试策略冷却或切换；不能把每次429都猜成五小时耗尽 |
| 没有可靠reset_at | 标恢复时间未知，使用配置的保守探测间隔且只有一个组级探针；不能伪造精确恢复时刻 |
| 请求超时/断线但可能已收费 | 先查回执/已持久化结果，按C05§1.9.3保留outcome_unknown及预留；不得立即对所有备用并行重发 |
| 已返回有效低分/缺证据 | 接受分数或unknown缺口，不为了高分换模型重问 |
| 所有模型都不可用 | waiting_for_provider，保存待办与最早可知恢复点；退出本次有界运行或等待到期事件，不死循环请求 |

max_attempts_per_dispatch_round限制同一逻辑题在一轮派发中的实际尝试。耗尽后保存轮次及retry_eligible_at，仅到期或收到有效恢复事件才原子开启下一轮；重启或点击不重置尝试轮。所有轮次共用原总预算/截止条件，成功题不进入下一轮。

熔断通知所有worker，已发请求不能假装撤销；仍接收/记账其迟到回执。冷却到期后单探针半开，成功再恢复并发，失败延长冷却。跨进程、重启、换模型均保留额度、冷却、在途/结果不明记录。这里使用普通“熔断”机制，不在本轮建立系统定时任务或承诺后台永久运行。

## 发包记录与防重复

至少记录：logical_question_id、pack_id、attempt_id、entity/security/segment、field/题义/方法版本、刷新代次、原截止日、policy版本、provider/实际模型、prompt/input hash、发送/返回UTC、请求ID、搜索/费用回执、状态及observation_id。只保留必要短问答和元数据，不记密钥或公司文档正文。

primary逻辑题键不因fallback模型或run_id变化而改变；comparison才把目标模型和比较组加入键。StockWiki计算fresh缺口，StockQA用持久化逻辑键防止两个worker同时再问。换模型排序不自动使所有公司失效。

题包6题返回4题成功时先逐题写这4题，只把2个缺失/无效题重组为新包；新的包ID不意味着新建所有逻辑题。已完成但未入库先重投outbox；已发送结果不明先对账；明确尚未发出才可安全重派。下一次继续不以“上次公司没全做完”为理由整家公司重问。

成功记录不等于永久不问：过期、新事件、题义变化或用户显式刷新可创建新代次。供应商未知等正常缺口采用独立重试冷却，不标fresh，也不每次启动立即再收费。

相关实现卡为Q04/Q06—Q10/O02与Q11，设置和UI为X03/X04/X06。新增PAR-01—08覆盖组共享额度、拒绝切换、部分包和并发防重；这些是待实施生产验收，配置校验通过不代表已经并行调用过模型。
