# invest-quick-scan

用联网LLM问答快速了解上市公司，保存带时间、模型与来源的结构化评分和事实。题库支持公司类型、行业、生命周期及恢复观察的组合；不下载或保存公司财报、公告、网页全文。

## 启动界面

在本项目根目录运行：

```powershell
python -m pip install -r requirements.txt
python scripts/open_dashboard.py
```

终端打印本机地址，默认 `http://127.0.0.1:8765/`。端口被占用时使用其他空闲端口，以终端输出为准。浏览器打开后进入工作台。五个工作区为总览、扫描、公司研究、题库和设置；各自包含原有子页面，旧地址仍可使用。可维护名单、查看原结果、按题义和分数条件筛选、比较不同观测，并预览和运行已登记扫描包。Ctrl+C停止服务。

界面源码默认位于同级目录 `iqs-question-bank-ui-lab`；运行环境需要Python。代码与数据目录分开时：

```powershell
python scripts/open_dashboard.py --ui-root "C:/path/to/iqs-question-bank-ui-lab" --data-root "C:/path/to/invest-quick-scan"
```

`--no-refresh`只查看已有展示快照；`--port 8766`指定首选端口；`--plan`只显示启动配置。正常打开页面和筛选不调用模型，不运行测试，不会补造缺失评分。

## 题库与公司结果

- 当前基础必做集合为通用核心24题、杜邦7题和波特五力5题，共36题。数量从题库派生，允许扩展；quick/full及分类未知时均保留。
- 公司类型、行业、阶段与属性题按真实适用性追加。杜邦/五力诊断单列，不重复计入核心质量均分；不适用须说明依据，缺证据留空。
- 当前评分题库48模块、222题，另有61道不评分的信息题。信息题面存在不代表公司事实已采集。
- 当前本机名单215家公司（原214家加经核实的腾讯）；已有12份旧草稿关联11家公司。尚无结果的公司明确显示待补，不将未知当0分或5分。历史缺少模型或题库版本时保持“未记录/未绑定”。

首页分别展示正式库覆盖和历史草稿；隔离真实工作区已签收腾讯36题及微软公司层面33题，三家公司的完整36题验收仍在进行，证券范围未齐不能算全公司完成。实时进度以PWF及原交付任务为准。结果详情可返回原筛选和快照；只有一条历史时显示暂无对照。完整理由、来源和元数据可展开，重大资格缺口保留在主层。

完整操作与配置见[工作台使用说明](docs/implementation/company-and-bank-ui.md)。生产结果直接读StockWiki；题库矩阵、旧草稿与旧选股器仍是明确分开的展示快照。2026-10-28的CATL与Microsoft历史单题恢复结果也保留在原工作区；它们不能替代本轮完整题库验收。原ACK验证工程交付，不代表金融准确性已通过或全名单已有结果。

设置页提供连接路径、模型顺位、共享额度、并发和预算字段表单，不必手写JSON；新扫描确认有效期可设0.25–24小时，默认1小时、较长扫描可选4小时，只影响之后明确准备的新确认，已有确认和预算不变。高级JSON仍可展开。保存由原服务校验，发生并发改动须重新读取，保存本身不调用模型。缺少合法原部署、模型或费用授权时，扫描仍会显示缺项。

首次连接时，复制[连接配置模板](examples/dashboard.config.template.json)到本机忽略文件 `config/dashboard.local.json`，填写原工作区与原运行目录；也可在界面的“设置”保存。高级连接JSON的`prepare.pack_size`控制之后新准备的实际题包大小；模型设置里的“每包最大题数”是策略上限，两者须一致兼容，保存不改变旧包。扫描输入和导入包必须登记到模板对应列表；详细字段、原预算约束及回执步骤见[产品接口与部署](docs/implementation/dashboard-product-contract.md)。未配置时会显示具体缺项，不从公司名临时制造身份、准入或预算。

本机现有真实工作区为隔离研究库，标签会显示这一点。已认可的214个既有实体已接入原StockWiki名单；本轮按原身份流程补入腾讯后共215家，210个verified、5个provisional。未按名称合并身份。名单里有公司不代表它已有评分。

### 在界面跑公司

“公司研究 → 公司对比”可按公司、模型、信息日期查看原始分数和理由。默认展示通用必答（含杜邦与五力），也可选择行业/阶段等模块或全部量化题库。题目数随题库变化；缺失留空，版本未绑定如实显示，不据此计算跨公司均分或宣称金融可比。

“扫描 → 名单维护”保留原手动增删/恢复入口，另可选择明确截止日期后开启 TXT/CSV 文件审阅。文件在本机解析，重复行保留出处；逐行向原身份库取候选，人工选实体并预览后才可明确提交。同名不自动合并。写入超时先核原状态，不重复提交；同一会话、连接、名单与截止日期的未决草稿在页面切换后仍保留。关闭或重载浏览器前请用“导出恢复草稿”保存，跨会话恢复须核原作用域，不能把仅观察到成员存在当精确操作ACK。

1. 打开“名单维护”查看或维护原名单；同一公司用唯一entity_id识别。新增成员先核身份候选，名称相似不自动合并。
2. 在“扫描任务”选择公司、信息截止日和quick/full，点击“预览公司题库与主体”。所有公司保留基础36题；经核实的行业/生命周期profile再追加专属模块，分类未知不猜。
3. 核对原分析主体。没有已登记主体时可明确选择“仅法律发行人”，它不代表已核实合并集团；多挂牌必须选择具体证券。确认准备只登记原输入，不调用模型。
4. 准备在后台进行，查看job状态；中断后用“核原状态并接续登记”，不会重复申请原准入。准备完选择完整公司组，也可全选无歧义组，预览并启动批次。
5. 批次按原预算、缓存和配额逐scope核验后执行。同公司经营题和证券题分别执行，全部完成才算该公司完成；安全暂停保留未完成部分，服务重启后须明确恢复。
6. 旧进程确认已停止但引用仍阻挡设置时，先“核原状态”，再用“归档已停止任务（保留工作和结果）”；未知/在途工作不允许归档。此动作只退役本地启动引用，不代表扫描完成。
7. 点击“入库并对账”或批次的交付按钮，后台复用原封存包，跟踪交付job及实际ACK。accepted/partial不是delivered，ready也不是金融审查通过。随后到“生产结果”“历史与模型”查看。

列表刷新超时不代表任务或答案被删除，也不表示原启动已经停止。先刷新并核对原状态，不重复点击启动；若显示“陈旧快照”，旧表只供查看，操作须等原服务重新读取成功。原任务预览最多等待150秒，明确启动及恢复最多等待180秒；浏览器超时不会取消后台请求。入库期间先等交付完成，再恢复扫描或保存运行设置，避免与原服务的写操作冲突。

服务重启后先“核原状态”，按原允许动作恢复。执行委托有有效期；过期或撤权不会因预算仍有余额而自动恢复。原任务恢复继续已登记的待问题目，不会把失败题自动变成新一次调用。需要补失败题或重新取得授权时，重新准备，保持原公司、信息截止、分析主体、题目语义和模型；原系统按现有状态决定复用成功结果、接续待办或创建获授权的新代次。已知收到但未形成有效答案的请求须先按原允许流程处置；未知请求不得盲重发。旧批次占位时，先暂停，再用“结束已停编排（保留工作与结果）”；只有原进程已确定退出、原工作没有未决请求时才允许结束。这仅结束编排，不删除原待办、答案、历史或费用，不能用于重发未知请求。

原任务恢复与新任务缓存是两回事：同一个已登记任务可恢复已接受的检查点，入库后的历史结果和ACK仍可查看；普通新扫描仍按来源信息日和原有效期判断新鲜度。过期、缺日期或证据不足应如实显示，不会因重启或入库变成新鲜结果。接续旧任务时还须沿用它的quick/full模式；quick也保留全部基础36题，不可为改标签覆盖原绑定。

长联网请求还需留足单次工作处理时长：高级连接配置可为新准备设置`prepare.work_lease_seconds: 3600`（省略沿用600秒），新扫描确认可独立设置12小时。两项都只作用新准备/新claim，不延长旧任务，也不增加预算。HTTP读取超时并不保证请求总时长；迟到回复仍须保留真实费用和回执，按原恢复流程处置，不能直接重发。完整时长分工见[产品配置说明](docs/implementation/dashboard-product-contract.md)。

首次扫描需在“设置”接好原部署、模型顺序和预算。模板中的`prepare`默认空，缺项会逐项显示；普通自动准备支持原owner policy 1.0/1.1；专用1.2恢复子集用于原owner明确批准的不可交付检查点，须按[受控恢复契约](docs/implementation/controlled-recovery-subset-contract.md)配置精确引用，界面将单列恢复题数与完整题库题数，不能据此宣称整家公司完成。高级策略不会自动降级。填写方法见[自动准备配置](docs/implementation/dashboard-product-contract.md#自动准备与批量操作)。旧r25实验的6次请求已用完并保留；本机已另建u25-live新原预算（USD25、最多250次模型HTTP、并发3），配置MiMo Pro原生联网并开启思考。2026-10-28，两条历史故障题已恢复并取得原ACK 2/2；当前继续验收A股、港股、美股三家公司的完整36题扫描、入库与缓存恢复，尚未全部通过。金融内容仍须按证据状态审查，不能把软件流程通过等同于金融结论已核验。打开UI或新增名单不扩大预算。原准入包含多次校验，可能耗时数分钟；浏览、题库预览和准备不调用付费模型，只有明确启动且原预算通过后才可能收费。

## 生成问题与验证输出

```powershell
# 导出完整基础题（StockQA兼容格式）
python scripts/question_sets.py basic --output runs/basic-questions.json

# 按公司profile组合专属模块，不调用模型
python scripts/question_sets.py compose --profile examples/profile.json --mode quick --out-dir runs/example

# 验证默认基础出题，不调用搜索或模型
python scripts/thin_scan.py --company "宁德时代" --out runs/basic-dry-run --dry-run --as-of 2026-10-25
```

`examples/profile.json`是演示配置，需要替换为经核实的公司分类与时间。`main_questions.json`和旧24题清单仅作历史兼容；新完整基础模板是 `basic_questions.json`。冻结路由、新旧版本兼容和标准答案命令见[SKILL.md](SKILL.md)。薄草稿不等于StockWiki正式观察或金融准确性验收。

## 项目分工与配置

| 项目 | 职责 |
|---|---|
| invest-quick-scan | 题库、路由、评分/事实契约、组合和产品薄接线 |
| StockQAbyLLM | 模型与搜索、原任务/预算账本、配额切换、重试及缓存恢复 |
| StockWiki | 公司身份、挂牌与名单、不可变观察、导入ACK及查询 |
| company-wiki | 复用已有身份与共享引擎基础能力；快扫不要求下载公司文档 |

API密钥只放环境变量，不填README、JSON、Excel或浏览器日志。模型顺序与共享额度模板见[模型配置](examples/model-policy.template.json)；检索失败、结果不明和fallback规范见[搜索与LLM实操](references/search-and-llm-playbook.md)。
